# CLAUDE.md

Guidance for Claude Code working on the Leeward project.

For human-facing developer setup (prerequisites, Godot MCP bridge, contribution flow), see `CONTRIBUTING.md`. This file is Claude-facing.

## Project Overview

Leeward is a Godot 4.6 naval sailing game (Age of Sail) using the Forward Plus renderer. It's a turn-based tactical game where players command ships on a hex grid, plotting movement and combat across a 10-phase turn cycle. Architecture is server-authoritative with a State-Controller-View pattern.

**Rules authority:** the game implements *Close Action* (1997). The rules are `docs/rules/close_action.md` (OCR of `docs/CoA_-_Close_Action_the_Age_of_Fighting_Sail_vol_1_1997.pdf`, with the charts as images in `docs/rules/images/`). Where Leeward differs from them, deliberately or not yet implemented, is tracked in `docs/rules/feature_diff.md`, which must be updated whenever a game feature is added or changed. Invoke the `close-action-rules` skill before building, testing or fixing game logic.

## Tooling (MCP Servers)

**Prefer the `godot-mcp` MCP server for Godot interactions whenever possible**, instead of ad-hoc shell commands. It is the most reliable way to drive the editor and a running game. Use it for:
- Running/stopping the project (`run_project`, `stop_project`) and reading output (`get_debug_output`).
- Checking the running game for problems: `game_get_errors` (push_error/push_warning + parser warnings) and `game_get_logs` (print output). After editing GDScript, relaunch and confirm `game_get_errors` returns zero — this is the canonical way to verify a clean build.
- Inspecting/driving the live game (scene tree, nodes, input, screenshots) via the `game_*` tools, and project/scene/script management (`read_scene`, `read_project_settings`, `list_project_files`, etc.).
- Note the in-game interaction server (`scripts/mcp_interaction_server.gd`) binds `127.0.0.1:9090`; the `game_*` tools connect to it. If `game_get_errors`/`game_get_logs` returns "No active Godot process" right after launch, it's a startup race — wait ~1s and retry.
- **Clicking the UI**: `game_click(x, y)` takes **window pixels**, not UI coordinates. Multiply a control's `get_global_rect()` position (or `Camera3D.unproject_position()` for a hex or ship) by the root viewport scale, `get_tree().root.get_final_transform().get_scale()` (about 1.89 on a Retina display), before clicking. Unscaled coordinates land on the wrong spot and look like ignored clicks. Drive the UI with real clicks rather than by emitting control signals.
- A script error inside `game_eval` freezes the running game; stop and relaunch it.

**For Godot API docs, use the `context7` MCP server with library `/godotengine/godot-docs`.** Call `context7` (`query-docs` against `/godotengine/godot-docs`) before relying on memory for engine/class/method APIs — training data may lag the 4.6 API. Skip the `resolve-library-id` step; this project's library ID is fixed.

Uses [GUT](https://github.com/bitwes/Gut) v9.5.0 (`addons/gut/`). Tests live in `test/unit/` and extend `GutTest`.

```bash
make test                         # Run all tests (headless)
make test-verbose                 # Run all tests with detailed output
make test-file F=test/unit/test_data_manager_ships.gd  # Run a single test file
```

Test naming: files prefixed `test_`, methods prefixed `test_`. Use `before_all()` / `before_each()` for setup.

Manual testing also available via scenarios and the Developer UI (F12 in-game).

## Architecture

### State-Controller-View (SCV)

- **State layer** (`scripts/state/`): `Ship` (immutable identity + type data), `ShipState` (mutable game state, references `Ship`), `EnvironmentState`. Serializable, deterministic. No logic.
- **Controller layer** (`scripts/server/`): Server-authoritative game logic. All state mutations happen here. Controllers check `is_server` before mutating. Clients are read-only.
- **View layer** (`scripts/view/`, `scripts/ui/`): Presentation only. Reads state, renders visuals. Never mutates game state.

### Autoload Singletons

- **GameState** (`scripts/autoload/game_state.gd`): Central state container. Holds all ships, environment, turn/phase, state history. Creates and owns all server controllers in `_ready()`.
- **DataManager** (`scripts/autoload/data_manager.gd`): Loads and caches JSON data (movement tables, ship definitions, scenarios). Provides lookup methods. `DataManager.combat_tables` is the `CombatTables` instance holding the 1997 combat charts.
- **Trace** (`scripts/autoload/trace.gd`): Lightweight tracing/logging autoload. **Required** in runtime code — `.claude/hooks/block_raw_print.py` blocks raw `print()` at Edit/Write time. Exempt: `scripts/util/`, `scripts/utils/`, `scripts/autoload/trace.gd`, `scripts/autoload/mcp_server.gd`, `addons/`. Per-line bypass: trailing `# allow-print`. Covered by `test_trace.gd`.

**Auto-test hook**: `.claude/hooks/run_related_tests.py` runs `make test` automatically after editing files in `scripts/server/`, `scripts/state/`, `scripts/core/`, `scripts/autoload/`, or `test/unit/`. Configured as a `PostToolUse` hook in `.claude/settings.json`.

Note: `scripts/autoload/mcp_server.gd` lives in this folder but is **not** an autoload — it's wired through the `godot_mcp` editor plugin.

### Turn Phase Cycle (10 phases)

SETUP → ENVIRONMENT → PLANNING → MOVEMENT_RESOLUTION → COMBAT_RESOLUTION → DRIFT_CALCULATION → STATUS_ADJUSTMENT → MORALE_CHECK → MESSAGE_DELIVERY → POST_COMBAT → END_TURN → (back to ENVIRONMENT)

Managed by `TurnPhaseController`. All phases do real work except MESSAGE_DELIVERY (stub, auto-advances). The `GamePhase` enum is unchanged; combat's two steps are `TurnPhaseController.CombatStep` (`NONE`, `DECLARE`, `RESOLVE`).

- **ENVIRONMENT**: `EnvironmentController.tick_environment` (wind/sea rolls via `Dice`). 3.B.6: it first applies the change rolled last turn (`EnvironmentState.pending_wind_speed` / `pending_wind_direction`, −1 = none), then rolls next turn's change and stores it as pending (WIND event with `forecast: true`; the minimap shows it).
- **PLANNING**: on entry `boarding_controller.take_link_snapshot()` records the ships fouled or grappled to each ship (`GameState.linked_at_plot`, 10.A.2: only those may be boarded this g-t). AI ships plot (`StubAI.plot_all_ai_ships`, then `assign_crew`, which also sets each AI ship's boarding order); the player plots movement, optional sail-change orders and (crew overlay) crew sections through `player_plot_crew` / `player_set_crew_auto`; the AI side's plan counts as submitted as soon as PLANNING begins (`ai_player_ids`, set by `GameState.start_scenario`; empty in headless tests, which submit for both); waits for `player_submit_plan(0)`. Movement plotting requests are refused outside PLANNING (SETUP excepted, before any turn loop) and once the player's plan is in. When every player is ready, `crew_task_controller.finalize_plots()` makes each crew plot legal against the final movement plot before the phase advances.
- **MOVEMENT_RESOLUTION**: `CrewTaskController.begin_turn_tasks()` turns the crew plots into tasks (sail changes start; sections at the braces for a turn at MA 0 become a T task, which the Tacking roll reads: +2 per section short of 3, at most +6, 5.D.2a; sets `plotted_sections`), then the movement resolver runs (sets `moved_this_turn`, `mp_used_this_turn`). Waits for the view to call `on_playback_completed()`, which applies results and then calls `crew_task_controller.after_movement()` (a hull repair ends on a ship that moved more than 4 MPs, 8.F.3b). **Bearing off (6.D)** is the owner's decision: ships of players in `bear_off_prompt_player_ids` (`GameState.start_scenario` sets the human players, `[0]`; empty in headless tests) stop the resolution at a potential collision — `run()` returns a log with `pending_bear_off` (a `MovementTypes.BearOffSituation`), the view plays it up to that segment and calls `on_playback_paused()`, which emits `bear_off_decision_requested`; `player_submit_bear_off(player_id, ship_id, choice)` ("port"/"starboard"/"collide"; returns "" or a reason) re-runs the resolver with the answers so far (`_bear_off_decisions`, same RNG start, so the prefix repeats) and the new log has `resume_impulse` = that segment. Other ships decide by `StubAI.bear_off_choice` (always bears off when a turn is legal; never rams). Success amends the plot (turn, then ahead to the deceleration minimum) and replays like an overlap rollback; once per g-t. Tests that want a plain collision pass `{ship_id: {"choice": "collide", "segment": n}}` as `run()`'s third argument.
- **COMBAT_RESOLUTION**: first `boarding_controller.declare()` announces the boarders away (BA tasks begun this g-t; the defender's marines are replotted to FB, 10.C.3; a struck or undefended defender is captured at once, 10.E.2a–b; several ships boarding one each get an action and share out her defence, a sixth boarding ship takes her outright, 10.F.2). Fire declaration is a step inside this phase (targets are chosen after movement). If neither `gunnery_calculator.any_eligible_shot()` nor `marine_fire_resolver.any_eligible_marine_shot()` is true: with a boarding announced or an action in progress the phase goes straight to `RESOLVE` and fights the boarding alone (emits `combat_log_ready`), else it is skipped (`combat_step` stays `NONE`). Otherwise `DECLARE`: emits `fire_declaration_requested`, the AI submits via `StubAI.submit_fire_orders()`, the player via `player_submit_fire_orders(player_id, orders, marine_orders := [])` (marine orders are `{ship_id, target_id}`; returns "" or a rejection reason; orders are hidden until both are in). Then `RESOLVE`: `marine_fire_resolver.prepare()` captures the marine shots, `gunnery_resolver.resolve()` computes all shots against start-of-step state and applies damage, then `marine_fire_resolver.resolve()` rolls the marine shots (7.G.5: boxes at the start of the step; dice after all gunfire), then `boarding_controller.resolve()` fights every live boarding action one round (10.C.4; all rounds rolled first, results applied together, 10.F.3), emits `combat_log_ready`; waits for the view to call `on_combat_playback_completed()`.
- **DRIFT_CALCULATION**: `drift_resolver.resolve()` for stopped ships; ships fouled or grappled together drift as one group (8.A.6: connected over `ShipState.linked_ids()`, one d10 by the member least likely to drift, no partial drift, any blocked hex holds the group).
- **STATUS_ADJUSTMENT**: first grappling, then ungrappling (8.C, SoP V.C–D; `grappling_controller.resolve_grapples` / `resolve_ungrapples`). Each is a **maintenance-orders step** (`TurnPhaseController.MaintenanceStep` `GRAPPLE`, `UNGRAPPLE`), modelled on the bear-off pause: a player in `maintenance_prompt_player_ids` (set with the bear-off ids; empty in headless tests) who has a choice (`maintenance_options(player_id, step)`: an eligible grapple, or a grapple to cut) is asked through `maintenance_orders_requested(player_id, step, options)`, and the phase waits (`advance_phase` is ignored) until `player_submit_maintenance_orders(player_id, {"grapple": [[ship, target], …]})` (or `{"ungrapple": …}`; returns "" or a reason; checks phase, waiting step, player, ship ownership and that each pair is one of the options). No choice, no pause. Every other player's ships are ordered by `StubAI.grapple_orders` / `ungrapple_orders`. The ungrapple step comes after the grapple rolls, so the player may cut a grapple made the same g-t. Then `critical_hit_controller.resolve_fixes()` (8.D.5 fix rolls for lasting crit effects; sheets cut expires), then `fire_controller.resolve()` (the Fire & Explosions sub-phase, SoP V.F: firefighting, fire damage, growth and spread, explosion rolls, unfought-fire MCs), then `crew_task_controller.advance_tasks()` (crew tasks counted, completed or cancelled; repairs are recorded (8.F.5, `REPAIR` event), RO completes and sail changes complete here; FB completes into a BR task), then a third maintenance step, `MaintenanceStep.PRIZE` (10.G.6): a prompted captor whose boarders finished RO with more boxes than the minimum prize crew chooses its size (`maintenance_options` → `BoardingController.prize_size_options`; `player_submit_maintenance_orders(player_id, {"prize_size": {action_id: n}})`, minimum to the surviving boarders; an action not named keeps the minimum; the AI by `StubAI.prize_sizes`), then `boarding_controller.advance_reorganizing()` (the prize crew of a won action whose boarders finished RO goes aboard, 10.G.7). In the fire sub-phase a prize's fires are fought by her original crew below (10.H.3, `FIRE_FOUGHT` with `below`). Unfouling and ungrappling skip pairs locked in a boarding action (8.C.5, 8.D.4).
- **MORALE_CHECK**: `morale_controller.resolve_checks()` rolls the checks noted during the turn; failures lower crew quality or strike the ship.
- **POST_COMBAT**: waits for the player to press End Turn (`player_end_turn(0)`); `advance_phase()` is ignored here. No timer.
- **END_TURN**: `victory_controller.check(turn)`. A non-empty result is stored in `phase_controller.game_result`, `game_over` is emitted, and the loop stops (phase stays END_TURN, `advance_phase`/submits are refused). Otherwise `boarding_controller.end_of_turn(turn)` keeps the turn's actions in `GameState.boarding_history` and drops finished ones (a repulse is kept one g-t for counter-boarding), flags are cleared and the next turn begins; at its start `boarding_controller.start_of_turn()` retakes any prize whose prize crew is below the minimum against an original crew of at least twice its boxes (10.H.4, `RECAPTURED`). A side with no ship in play (prizes do not count) is defeated.

The gunnery and marine fire resolvers and the damage, critical-hit, drift, fouling, morale, crew-task (and its handlers: sail, fire, repair, boarding tasks), grappling and boarding controllers append typed events to `GameState.turn_log` (`PhaseEvents.PhaseLog`, made by `GameState.new_turn_log`, which stamps each event with the controlling side of every ship it names, `PhaseEvent.players`; the combat log labels ships "(yours)"/"(enemy)" by that, so a later capture does not relabel earlier lines); the environment controller logs WIND, the movement resolver COLLISION, STOPPED_SHORT, IN_IRONS and TURN_UNDONE, and `TurnPhaseController` adds HOLD_FIRE (ships that could fire but did not) and the VICTORY event at END_TURN; planning logs no events; finished turns are kept in `GameState.turn_logs[turn]`. The UI renders these as the combat log.

When changing a phase method, invoke the `phase-implementer` skill (`.claude/skills/phase-implementer/`). It codifies the SCV pattern (server-authority guard, `game_state.dice`, automatic state-history snapshots, GUT test template).

Other project skills: `close-action-rules` (where the authoritative rules and charts are, and keeping `docs/rules/feature_diff.md` current), `scenario-creator` (create scenario JSONs), `gen-test` (scaffold GUT test files). The `scv-reviewer` agent (`.claude/agents/scv-reviewer.md`) audits State-Controller-View pattern adherence across the codebase.

### Server Objects on GameState (created in `_initialize_server_controllers()`)

All except `dice` (takes the RNG) and `fire_geometry` (takes a `HexGrid`) take `game_state` in `_init` and reach collaborators through it. Names are exact. A game is started with `GameState.start_scenario(scenario, human_player_ids)` (server only): it builds the scenario's ships (type, navy), sets the prompt and AI player ids, then `start_new_game`; the view makes its ship views on `game_started`.

- `dice` (`Dice`): the default source of randomness for game logic (see Dice below).
- `fire_geometry` (`FireGeometry`, `scripts/core/`): pure geometry — `bearing_side` (which broadside covers a hex from a battery hex, or -1), `range_between` (closest hexes), `battery_bears`/`in_battery_arc` (per-battery arc and LOS), `rake_type_ships`, `has_line_of_sight`, `broadside_hexes` (per battery hex; callers draw bow ∪ stern).
- `gunnery_calculator` (`GunneryCalculator`): pure queries, no dice, no mutation (declaration rules delegated to the static `FireRules`) — `preview(order, two_targets)` gives a `ShotPreview` (modified gunfire number + modifier breakdown), `eligible_shots`, `any_eligible_shot`, `validate_orders`. Types in `gunnery_types.gd` (`FireOrder`, `ShotPreview`; aims `low`/`high`, ammo `round`/`dismantling`).
- `gunnery_resolver` (`GunneryResolver`): rolls and applies a set of `FireOrder`s simultaneously, logging each shot.
- `marine_fire_resolver` (`MarineFireResolver`, 7.G): pure queries `preview(ship_id, target_id)` (boxes, column, DRMs, `hit_max`, `chance`), `eligible_marine_shots`, `any_eligible_marine_shot`, `validate_orders(player_id, orders)` (eligibility in `FireRules.marine_error` / `marine_orders_error`); `prepare(orders)` then `resolve(shots, phase)` roll one d6 per firer in ship_id order and apply the boxes through `DamageController.apply_crew_losses` (Crew Loss "All Other Causes", no roll when the target has one crew type). Logs MARINE_FIRE, then DAMAGE with cause `marine_fire`. The boarders −1 reads live FB/BR/BA tasks (`has_boarders`); the grappled-or-fouled DRM reads `linked_ids()`.
- `damage_controller` (`DamageController`): applies rigging/hull/crew boxes (lowest section first), dismounts guns on hull-section loss, notes morale checks, strikes ships.
- `critical_hit_controller` (`CriticalHitController`): critical hits (7.D.7–12) — the gunfire crit roll (natural 6, then CH d6 + `ch_modifier` ≤ CH#), the Rigging/Hull Crit tables by aim, a FIFO queue of rigging/hull checks for emptied sections (`DamageController` queues them; `drain` chains 7.D.12), lasting effects in `ShipState.critical_effects` (read via `ShipState` helpers: `obscured_penalty`, `critical_mp_loss`, `max_turns_per_gt`, …), hull #10 fire roll (d10 + SK ≥ 6) and hull #12 afire through `fire_controller.start_fire`, a hull #12 explosion through `fire_controller.explode` (DESTROYED, then blast and debris), hull #4 crew disorganized (`_disorganize`: the highest sailor section not already disorganized is forced onto RO via `crew_task_controller.force_task`), rigging #3 `signal_halyards_cut` (fixable; blocks nothing until signalling exists), and `resolve_fixes` (8.D.5) in STATUS_ADJUSTMENT. Tables in `data/rules/critical_hits_table.json` and `poor_maneuvering_table.json`.
- `fire_controller` (`FireController`, `scripts/server/fire_controller.gd`): fires and explosions (8.E, 9.B.1c–d) and the FF crew-task handler (registered as `FF`). `start_fire(ship_id, cause, phase, source_id, in_fire_subphase, extra)` (adds a `ShipState.fire_list` entry; its fear MC, trigger `fire_<seq>`, none when struck; a section on fire watch, FF with fire −1, is attached at once), `resolve(phase)` (dice order in the code: firefighting d10s, then 1H+1R per fire burning since this g-t or earlier, then growth (every 5 g-t's) and spread (d10 ≤ 4 + SK of the fouled ship), then 2d6 explosion rolls for burning ships with no hull boxes (≤ 2 + `explosion_checks`), then an MC per fire that existed at plotting with no FF task), `explode(ship_id, phase)` (destroy, then blast at range 1–2 from `fire_table.json` as the MGN on the firing-high column, then flaming debris d6 ≥ range within 6, fouled ships always), `skill(ship)` (CQ G once struck). Fires made in the Combat Phase burn that g-t; fires made in the sub-phase burn from the next. Readings: better crews resist fire (spec §9 Q1). A struck ship fights its fires (automatic allocation, CQ G, no MCs); `DamageController.strike` ends its other tasks. Developer UI: `dev_commands.start_fire(ship_id)`.
- `repair_controller` (`RepairController`, `scripts/server/repair_controller.gd`): the RR, RH and RS crew-task handler (one instance registered for all three; 8.F, 9.B.2). Statics used by `CrewRules`/`CrewAuto`/the overlay: `refusal(ship, code)` (8.F.3: something to repair at plot time; RR only at FS, furled or dismasted, 8.F.3a; struck ships make none), `mp_warning(code, ctx)` (RH with more than 4 MPs plotted), `is_repair`, `max_mp`. Handler: `cancel_reason` (nothing left, or RH after > 4 MPs: `after_movement_reason`), `counts_turn` (not the g-t of an 8.F.6 reset, `reset_turn`), `on_complete` (`ShipStateController.repair_box(ship_id, kind)` → the section taking damage, or the one before it when full, section 4 when dismasted; RS removes the oldest `shrouds_severed`; logs `REPAIR`). `DamageController` sets `ShipState.checked_sections` the first time a section empties, and a section emptied again queues no Rigging/Hull Check and (hull) dismounts no guns (8.F.5, 9.B.2); `DamageController.rigging_hit_while_dismasted` (from `apply_hits`, gunfire and blast) calls `crew_task_controller.reset_progress(ship_id, "RR", …)` (8.F.6). Developer UI: `dev_commands.damage_ship(ship_id, rigging, hull)`.
- `sail_controller` (`SailController`): sail changes as the SAIL crew-task handler: `available_targets`, `change_cost`, `plot_sail_change` (sets `plotted_actions.crew_orders.sail_target`), `cancel_change`.
- `crew_task_controller` (`CrewTaskController`): the crew-task engine (4.A.3, 4.B; `docs/superpowers/specs/2026-11-15-crew-tasks-fire-repairs-design.md` §3). One `CrewTaskHandler` per code (`register_handler`; SAIL = `sail_controller`, T = `TackCrewHandler` (one g-t, 1–3 sections), RO = `ReorganizeHandler` (forced, 5 g-t's ± SK counted from the g-t after it began; handler hook `counts_turn`)). `plot_crew`, `set_auto` (players reach both through `TurnPhaseController.player_plot_crew(player_id, ship_id, plan)` / `player_set_crew_auto(player_id, ship_id, on)`, which also check PLANNING, ownership and that the plan is not yet submitted), `current_plan(ship_id, end_planning := false)` (while planning, braces placed before the MA-0 turn is plotted are kept with a warning; `end_planning` drops them, as `finalize_plots` does), `planned_tack_sections` (for the planning tacking note), `finalize_plots`, `begin_turn_tasks`, `after_movement`, `advance_tasks`, `cancel_task`/`cancel_section`/`cancel_code`/`drop_all`, `force_task`, `reset_progress`. Plans are legalised by the static `CrewRules.normalize` (`scripts/server/crew_rules.gd`; also `refusal`, `assign`, `guns_preview`, `stations` (what the crew overlay draws), `progress_warning`, `with_sail_order`, `fire_draft`/`fill_fires` (8.E.2; fires come from `ctx.fires`, the ship's `fire_seqs()`; fire stations `fire_<seq>`, fire watch `fire_-1`)); with `ShipState.crew_auto` (default on; AI always) the sections are placed by `CrewAuto.allocate` (`crew_auto.gd`: locked tasks, fires (the draft), tasks in progress, then the ordered sail change, then up to 3 sections at the braces when `CrewRules.context` sees a turn at MA 0 (`ma0_turn_plotted`, via `MovementResolver.plots_ma0_turn`), in worker order M, S4, S3, S2, S1, marines held back by a fire, a fixable crit, fouling or an adjacent enemy, then repairs (A5: RS, RR, RH; the marines if free, a sailor only with no enemy within 15 hexes)). A plan not yet stored this turn (`plotted_actions["crew_plotted"]` false; `begin_turn_tasks` clears it with `ShipStateController.clear_crew_plot`) is the carry-over default (`CrewRules.plan_of` → `default_plan`: tasks in progress stay with their sections), so a manual ship keeps its repairs and fire parties from turn to turn. Task lengths come from `data/rules/crew_tasks.json` (`CombatTables.task_turns`).
- `drift_resolver` (`DriftResolver`): drift of stopped ships, collision/fouling on blocked drift.
- `fouling_controller` (`FoulingController`): unfouling rolls for fouled pairs.
- `grappling_controller` (`GrapplingController`): grappling and ungrappling (8.C). Pure queries `grapple_options` / `grapple_chance` / `grapple_error` and their `ungrapple_*` twins (chances are `{needed, modifier, modifiers, percent}`); `resolve_grapples(orders, phase)` / `resolve_ungrapples(orders, phase)` roll (dice order in the file header) and log GRAPPLE / UNGRAPPLE. A grapple at WF=L sets that ship's speed to 0 (in irons, 5.D.5). `locked_in_boarding` / `marines_in_boarding` read the boarding state (8.C.5).
- `boarding_controller` (`BoardingController`, `scripts/server/boarding_controller.gd`): boarding actions and capture (10.A–H; boarding spec B4–B6). Actions are `BoardingAction`s (`scripts/state/boarding_state.gd`) in `GameState.boarding_actions` (`declared`/`engaged`/`attacker_won`/`defender_won`). Dice order in the file header. Developer request: `dev_commands.grapple_ships(a, b, count_now)` (server and debug builds only) grapples two adjacent ships to set up a boarding.
- `morale_controller` (`MoraleController`): rolls noted morale checks, lowers crew quality, strikes at quality G.

### Dice

`Dice` (`scripts/server/dice.gd`) wraps `GameState.rng`: `d6()` is 1–6, `d10()` is **0–9** (as on the 1997 charts), `two_d6()`, `two_d10()` is **0–18**. **New game logic must roll through `game_state.dice`** — never call `randi()` or `rng` directly. Known, accepted exception: `MovementResolver` still rolls directly from its `rng` property (`rng.randi_range`/`rng.randf`; it uses `game_state.rng` unless an explicit RNG is set), and `EnvironmentController` still passes `game_state.rng` into `_update_weather`. `ScriptedDice` (`test/unit/scripted_dice.gd`, a `Dice` subclass) returns queued values (`queue([...])`; `two_*` pop two) so tests can fix rolls.

### Movement Plotting Protocol

Session-based async system in `MovementPlottingController`/`MovementPlottingSession`:
- Requests: START_PLOTTING, SELECT_HEX, UNDO, SUBMIT_MOVEMENT, CANCEL_PLOTTING

## Key Data Formats

### Movement Allowance Table (`data/rules/movement_allowance.json`)

5-level nested lookup: `speed_type → wind_facing → wind_speed → rigging_quality → sail_state → MA`

- Speed types: `L/F`, `L/S`, `L/VS`, `F/F`, `F/S`, `F/VS`, `C/F`, `C/S`, `C/VS`
- Wind facings: `C` (close-hauled), `B` (broad reach), `R` (reach), `L` (luffing — always returns 0)
- Wind speed: `1`–`4` (string keys). Wind speed 0 (calm) is not in the table: `ShipStateController.get_movement_allowance` and `MovementValidator._lookup_ma` return 0 before the lookup.
- Rigging level: `1`–`4` = number of rigging sections that still have boxes (see Rigging level rule)
- Sail states: `fs` (fighting), `ms` (maneuvering), `ps` (plain), `ns` (no sail)

Access via `DataManager.get_movement_allowance(speed_type: String, wind_speed: int, wind_facing: String, sail_state: String, rigging_quality: int)`. Note the argument order does **not** match the JSON nesting order, and `wind_speed`/`rigging_quality` are `int` at the API even though the JSON keys are strings. The `rigging_quality` argument is the **rigging level** (1–4, asserted); level 0 (dismasted) must never reach the table — `ShipStateController.get_movement_allowance` returns 0 first. Callers pass `ShipState.movement_sail_state()`, not the raw `sail_state`.

**Rigging level rule** (Close Action 5.F): rigging level = number of rigging sections with at least one box (`ShipState.rigging_level()`, 0–4). Plain sail (PS) only at level 4; manoeuvring sail (MS) at levels 4–3; fighting sail (FS) until dismasted (level 0). `max_sail_state()` gives the cap; `movement_sail_state()` = lower of carried `sail_state` and the cap. A ship carrying more sail than its rigging allows is not forced down: it moves at the capped state but takes damage at the state it carries. Low-level rows in `movement_allowance.json` are keyed `fs` accordingly.

Validate after edits: `python3 .claude/skills/validate-rule-table/scripts/validate.py`. Catches typos (e.g. `"FS"` vs `"fs"`) that would silently return 0 at lookup time instead of erroring.

### Combat Tables (`data/rules/`, transcribed from the 1997 chart scans `docs/*.jpeg`)

Loaded by `CombatTables` (`DataManager.combat_tables`). Never take numbers from `docs/Close-Action-Rules-v6-1.txt` or `docs/07-naval-combat-mechanics.md` (non-canonical). Where rule text and chart disagree the chart wins (two-target modifier is −12).

- `gunnery_factor_table.json`: LG/MG/CR multiplier by range 1–15 → `gunnery_multiplier(gun_type, range)`.
- `basic_gunfire_number_table.json`: total gunnery factor (TGF band) × range → BGN; second value for French guns at range 11–15; blank = cannot fire → `basic_gunfire_number(tgf, range, french)`.
- `gunfire_results_table.json`: final gunfire number 1–52+ → FS/+MS/+PS columns for aim low/high, plus CH# → `gunfire_result(fgn, aim, column)`, `critical_hit_number(fgn)`. Slashed results (`r/c`) are resolved with a d6.
- `gunfire_modifiers.json`: range bonuses and flat modifiers → `range_bonus(kind, range)`, `flat_modifier(name)`, `sections_firing_modifier(n)`.
- `crew_loss_table.json`: sailor/marine split by cause → `crew_loss_is_sailor(cause, d6)`.
- `drifting_table.json`: sail state × wind speed number, class DRMs → `drift_number`, `drift_class_drm`.
- `unfouling_table.json`: success threshold by attempt → `unfouling_success_max(attempt)`; the +1 "marines not available" DRM (unfouling and 8.D.5 fixes, applied when `ShipState.marines_busy()`) → `marines_unavailable_modifier()`; the Ungrappling Only DRMs → `ungrapple_drm(name)` (`per_cq_better`, `friendly`, `ws4`).
- `boarding_combat_table.json` (read by `BoardingController`): the Boarding Combat 2d6 rows 4–12 (`pct`, attacker/defender special-result codes) → `boarding_row(dr)`; `boarding_loss_bcf(pct, roller_tbcf)` (static, nearest BCF, halves up); TBCF odds ladder → `odds_drm(friendly, enemy)` (rounded down to the listed ratio, integer compare); Other DRMs → `boarding_class_drm(defender_class, attacker_class)`; `prize_minimum(ship_class)`. BCF per box → `bcf(crew_quality, marine)` (from `crew_quality_table.json`).
- `grappling_table.json` (read by `GrapplingController`): `grapple_success_max()` (≤ 2), `grapple_drm(name)`.
- `marine_fire_table.json`: Marine Fire d6 by marine boxes → `marine_fire_result(dr, boxes)`, `marine_fire_column(boxes)` / `marine_fire_column_label(boxes)` ("7-8"), DRMs → `marine_fire_drm(name)`.
- `fire_table.json`: fires and explosions (8.E.4–11): `spread_number`, `growth_turns`, `explode_max`, `debris_radius`, `debris_never` → `fire_rule(name)`; the blast table → `blast_mgn(ship_class, range)` (−1 beyond range 2). Extinguishing uses `unfouling_table.json`.
- `crew_tasks.json`: the ship log's Crew Task Order Codes (sections, g-t's by CQ or `n ± SK`; FB/BR/BA/BD are the boarding tasks) → `crew_task(code)`, `task_turns(code, crew_quality)` (−1 open-ended), `task_sections(code)`.
- `crew_quality_table.json`: gunnery and SK modifiers by quality letter → `crew_quality_modifier`, `skill_modifier`.
- `tacking_table.json` and `bearing_off_table.json` (loaded by `DataManager`, not `CombatTables`): the TACKING and BEARING OFF d10 charts, stored as the chart's "roll ≤ n" numbers. `MovementResolver` applies the chart DRMs.

Validate after edits: `python3 .claude/skills/validate-rule-table/scripts/validate_combat.py` (row counts, BGN band gaps/order, result-string syntax, unexpected damage dips; exit 1 on error). Run both validators; `make test` covers spot-checked cells (`test_combat_tables.gd`).

Other rule lookups on `DataManager`: `get_speed_change(change_type, maneuverability)`, `get_tacking_number(maneuverability, wind_speed)` (d10 ≤ n succeeds; -1 at WS 0; `get_tacking_percent` is the base chance for display), `get_bearing_off_number(crew_quality, maneuverability)` (d10 ≤ n; -1 = NA), `get_min_heading_change_movement_required(direction, ship_speed, maneuverability)`.

### Ship Definitions (`data/rules/ships.json`)

Ship ids: `frigate_38`, `frigate_32`, `ship_of_line_74` (`corvette_24` was removed — no chart row). Each has: name, nationality, rating, class (2–3), maneuverability, speed_type, draft, `freeboard`, `rigging_hp[4]`, `hull_hp[4]`, `crew_count[4]`, `marine_count`, `gun_factors` (`{"lg","mg","cr"}`: gun factors **per side**, long guns / medium / carronades), `ch_modifier` (critical-hit modifier, added to the CH d6, 7.D.11), `lower_deck_modifier` (stored, unused), `point_costs` (victory-point cost keyed `"<crew quality><morale rating>"`, e.g. `"B3"`). `armament` is display-only history. Ships sailed by the French navy use the second BGN value at ranges 11–15 (1.G.8: `ShipState.is_french_gunned()`, from `ShipState.gunnery_navy()` = `navy` if set, else the type's `nationality`; `navy` comes from a scenario's per-ship `"navy"` or per-side `"navies": {"0": "British", "1": "French"}`, and a prize takes her captor's).

`ShipState` combat/turn-loop fields (all mutated only via `ShipStateController`): `status` (`ACTIVE`/`STRUCK`/`DESTROYED`/`CAPTURED`), `guns_dismounted[2]` and `initial_broadside_fired[2]` (per side), `crew_tasks` (live tasks have `ended == ""`; a sail change is a `SAIL` task, read with `sail_change_info()` / `has_sail_change()`), `plotted_sections` (sections on a task this g-t: they do not serve the guns, `sections_able_to_fire()`), `crew_auto`, `fire_list` (`{seq, created_turn, started_turn, cause}`; read with `fire_count()`, `is_burning()`, `fire_seqs()`, `fire_age(seq, turn)`, `fire_task(seq)`), `fire_seq`, `explosion_checks`, `mp_used_this_turn` (steps executed, turns included), `moved_this_turn`, `pending_morale_checks` + `morale_triggers_used`, `unfoul_attempts`, `grappled_with` (symmetric `Array[String]`; `ShipStateController.add_grapple` / `remove_grapple`; read with `is_grappled()`, `is_grappled_to(id)`, `linked_ids()` = fouled partner ∪ grapples, `is_linked()`), `ungrapple_attempts` (partner → tries), `starting_crew_quality`. `crew_count` is four sailor sections (indices 0–3), `marine_count` separate (section index `ShipState.MARINES` = 4), both initialised from the ship definition; `morale_rating` is 2–6 (higher is worse) and never changes; `crew_quality` is a letter A–G and falls on failed morale checks.

### Scenarios (`data/scenarios/*.json`)

Wind conditions, map config, ship placements with position (q,r), facing, sail state, crew quality/morale. Optional `turn_limit`, `navies` (1.G.8) and `year` (integer; ≤ 1783 gives the hull #12 explosion roll −1; absent = no year DRM). Full schema: `.claude/skills/scenario-creator/SKILL.md`.

## Conventions and Gotchas

### Hex Grid
- **Axial coordinates** (q, r) with **pointy-top** orientation
- **Direction numbering**: 0=E, 1=SE, 2=SW, 3=W, 4=NW, 5=NE
- **World/screen orientation**: world +X is east, −Z is north. `IsometricCamera` builds a right-handed basis (covered by `test_isometric_camera.gd`); `camera_rotation_y = 90` is north-up/east-right and only the player's camera controls change it. Selecting a ship never rotates or zooms the camera (`pan_to_if_needed` pans only when the ship is near the screen edge).
- **Owner colours**: green = human player's ships, red = enemy (`ShipView.owner_color`, shared by the map ring/pennant and the minimap).
- **All ships are 2-hex** (`ShipState.get_ship_size()` = 2). `ShipState.hex_position` is the **bow**; the stern is derived, never stored: `HexGrid.stern_of(bow, facing)` = neighbour in `(facing + 3) % 6`, or `ShipState.stern_hex()` / `occupied_hexes()` (`[bow, stern]`). A ship always sits on two hexes, never along a hex spine (5.A.2c). Position the model with `HexGrid.ship_center_world(bow, facing)`, not `axial_to_world()`. (`HexGrid.axial_to_edge_world()` is live — `ShipIndicatorModel` uses it to compute hex-face midpoints for the selection indicators.)
- **Occupancy** (`scripts/server/occupancy.gd`, `Occupancy`): `build(ships, exclude_ids)` and `from_positions(bows, facings, exclude_ids)` map every occupied hex to a ship id; `overlapping_ids`; `in_bounds(hex, scenario)` (both hexes must be on the map). `GameState.placement_errors()` checks scenario placements. `GameController.ship_at_hex(hex, ships)` (static) picks a ship by either hex.
- **Turns pivot on the bow**: the stern swings. A plot step's `hex` is the resulting bow (unchanged for a turn, new facing); `ValidMove.hex` is the click target (for a turn, the bow's neighbour in the new facing). A turn whose new stern is out of bounds is refused. In resolution each step enters one hex (ahead → new bow, turn → new stern); a stern may swing into a hex another ship holds or a bow enters (`OVERLAP`, 6.B.2) if the two ships no longer share a hex at the end of the next segment; otherwise the turn is rolled back (`OVERLAP_ROLLBACK`, "already occupied" or "bow precedence"): the turning ship's plot is amended to the steps before the turn plus any ahead steps its deceleration minimum needs, and the whole resolution is re-run from the same RNG state. Two sterns swinging into one hex with no further MPs plotted (6.C.1b), or two ships swinging onto each other's bows (complete overlap, 6.B.5), contest it with the 6.C.2 roll (`CONTESTED_HEX_ROLL`): the winner turns (stub: the winner always chooses itself), the loser's turn is cancelled (`STERN_BLOCKED` "lost stern contest to <id>", stop cause `stern_contest`), never a collision; a loser that must still meet its deceleration minimum has its plot amended with ahead steps and the resolution replayed, with the rolls put back into the final log. If either stern ship has further MPs it is a 6.B overlap instead ("sterns together" if not cleared). A ring of ships each entering another's old stern lets the lowest-id group go first, assuming the ship ahead leaves; if a ring member turns out to be stopped, the pass is re-run with the ring broken (its old stern held), as for overlap rollbacks. A replay reuses each stern contest's first winner and rolls rather than rolling again.
- **Speed** counts executed steps, turns included, if the ship moved ahead at least once, else 0; `moved_this_turn` means moved ahead at least once (5.E.2).

### Sides, Arcs and Rake
- Side indices: `ShipState.PORT = 0`, `ShipState.STARBOARD = 1`. Starboard is `facing + 1` / `facing + 2`; port is `facing − 1` / `facing − 2` (mod 6).
- **Batteries**: each side has two batteries, one at the bow hex and one at the stern hex. **Broadside arc** (per battery): the 60° wedge centred on the beam out to range 15. `FireGeometry.bearing_side` is an angle test (60°–120° off the bow, with a 0.5° tolerance), which corresponds to the hex rows of directions `facing ± 1` and `facing ± 2`. Ahead/astern are blind; no chase guns. A battery bears if at least one target hex is in its arc and every target hex in its arc has line of sight (target hexes outside the arc are ignored, 7.B.6); the ship's own hexes and the target's do not block. Range is measured to the closest hexes (7.C.4).
- **Battery orders** (7.B.1): `FireOrder.battery` is `full` (both batteries of the side must bear), `bow` or `stern`. A single battery is a half broadside: `half_broadside` (−8), except when the ship names two targets (only the −12 two-target modifier applies, 7.C.12g). `validate_orders` refuses a battery fired twice, more than two targets per ship, and bow+stern of one side at one target (declare a full broadside). A side may split (bow at one target, stern at another).
- **Previews**: `GunneryCalculator.preview_orders(orders)` previews a whole order set as it will resolve (two targets per ship; the initial-broadside bonus once per broadside, 7.C.10: the larger bonus, bow on a tie). The resolver and the fire panel both use it, so displayed numbers equal rolled ones; single `preview()` cannot know the rest of the set.
- **Fire rules live in `FireRules`** (`scripts/server/fire_rules.gd`, pure statics): target cap (`MAX_TARGETS`, `limit_targets`), bow+stern at one target = full broadside (`side_shots`), full before half (`battery_rank`), forced high aim and dismantling range (`make_order`, `effective_aim`/`effective_ammo`), and `declaration_error` (used by `validate_orders`). The calculator, the stub AI and the fire panel all call it; do not re-encode these rules elsewhere.
- **Fire panel** (`fire_declaration_panel.gd`, widget state and text only): one row per battery that bears on a target ("Full broadside" only when both bear, plus "Bow battery"/"Stern battery"), so a side can split between two targets or fire a half broadside at a target both batteries cover. The map highlights the chosen battery's arc (`GameController.battery_arc`). The no-shot reason comes from the bearing battery's preview. A "Marines" block per own ship whose marines may fire (7.G) lists each adjacent enemy with the Marine Fire column and the chance of a hit (`MarineFireResolver.preview`), plus "Hold musket fire"; the best shot is chosen by default. A ship with only a marine shot is listed too, so the panel opens. `GameController` reads `get_marine_orders()` and sends them with the gun orders in `player_submit_fire_orders`.
- **Rake** (`rake_type_ships`, 7.E.2): range (closest hexes) ≤ 5 and the firer is outside all four of the target's battery arcs, or directly ahead of its bow / astern of its stern and adjacent. Stern rake (firer aft of the target's beam line) doubles crew hits.
- Fire orders: per battery one target, aim `low`/`high`, ammo `round` (range 15) or `dismantling` (range 7). Ranges 10–15 are high only. Two targets = −12 on each shot.

### Ship Status
- A STRUCK ship cannot move, fire, change sail or unfoul and is not a valid target, but it still drifts and blocks line of sight and hexes. It may be boarded and is then captured without a fight (10.A.3).
- A CAPTURED ship (a prize, 10.H; `ShipState.is_captured()`) is under its captor's side: `ShipState.player_id` follows `controller_id` (−1 = the owner; `original_player_id` is the owner), and `GameState.ships_by_player` is re-indexed by `GameState.transfer_control`. It is out of play (cannot move, `SHIP_CAPTURED`, or fire, §8 Q2) but `is_targetable()` for its old side (10.H.1); `is_targetable()` = active or captured is the gunfire and marine-fire target test. Its live crew is the prize crew (empty until it goes aboard); `prize` holds `captor_id`, `original_crew`, `original_navy`, `prize_crew_aboard`, `fires_below`. With her prize crew aboard (`has_prize_crew()`, `crew_can_act()`) she plots only boarding and repairs (10.H.2; `CrewRules.normalize`, the overlay shows the guns idle and fires "fought by the original crew") and may be boarded (`can_be_boarded()`). Victory points go by original owner (`GameState.get_original_player_ships`); boxes detached as prize crew (`ShipState.detached_boxes`) are not destroyed sections. The map shows a prize flag and a "PRIZE · reorganizing n/m" label placed clear of the hulls (above the ship on screen, below or farther out when other ships are in the way; `ShipView.prize_label_place`); the minimap icon is hollow; the overlay's Guns readout says "Guns silent · a prize".
- A DESTROYED ship (an explosion: hull critical #12 or a burning hulk, `FireController.explode` → `DamageController.destroy`) is out of play like a struck one and counts as lost for victory, but it never drifts, fouls (its partner is freed when it blows up), burns (its fires are cleared) or takes damage; both its hexes still block movement and line of sight. `ShipState.is_out_of_play()` = not active (struck, destroyed or captured) — use it for "cannot act / not a target / lost" checks, and `is_struck()` only where a wreck must differ (drift). `ShipView` shows a procedural wreck; the minimap icon goes grey.
- A fouled ship (`fouled_with != ""`) cannot plot or execute movement (plotting returns `SHIP_FOULED`); it can still fire and be fired on. A grappled ship likewise (`SHIP_GRAPPLED`, 8.C.7); the map draws its grapples (`GrappleLines`, view) and its card carries the GRAPPLED badge. A destroyed ship drops its grapples. Dismasted and struck ships also refuse plots (`SHIP_DISMASTED`, `SHIP_STRUCK`).
- A `ShipState` whose `rigging_current_hp` is all zeros is **dismasted** (level 0, movement allowance 0). Test fixtures must set rigging explicitly.

### Tests and RNG
- Any code or test that assigns `GameState.rng` **must also assign `GameState.dice`** (`GameState.dice = Dice.new(GameState.rng)`); otherwise dice keep using the old RNG. `GameState.start_new_game` does both.
- `make test-file F=...` currently runs the **whole suite** (the GUT CLI picks up all of `test/unit`).
- `addons/gut/gut_loader.gd` carries a one-line local patch (`get_setting(..., true)` instead of `get()` for `exclude_addons`, absent in Godot 4.6). Keep it when updating GUT. `make import` prints `SCRIPT ERROR`s from the GUT editor plugin; they are noise.

### Server Authority
- All mutations guard with `if not is_server: push_error()` — never bypass this
- Controllers in `scripts/server/` are server-only; clients are read-only observers
- **Strict for ship state:** view-side code (`scripts/ui/`, `scripts/view/`, `scripts/core/`) never calls a `ShipStateController` or `EnvironmentController` mutator and never writes a `ShipState` field, even under an `is_server` check or an `SCV:ALLOW` comment. It sends a request the server validates and answers with "" or a reason: `GameState.start_scenario` (game start), `player_submit_plan` (its own player only), `player_clear_movement`, `player_submit_fire_orders`, `player_submit_bear_off`, `player_plot_crew` (also the boarding order), `player_set_crew_auto`, `player_plot_sail_change`, `player_submit_maintenance_orders`, and for the Developer UI `GameState.dev_commands` (`DevCommands`: server and debug builds only; `reset_game` restarts the scenario). Read-only queries (`get_`/`is_`/`can_`/`has_`) are fine. New player actions get a new server request method. `test_server_authority.gd` scans the view code (`scripts/ui`, `scripts/view`, `scripts/core`, `scripts/commands`) and fails `make test` on a violation (including GameState container and log mutators, `phase_controller` field writes, server controllers with no view-facing queries, any `CrewTaskController` call other than the queries `current_plan`, `planned_tack_sections`, `handler`, any `BoardingController` call other than its queries, and writes to `controller_id`, `prize`, `detached_boxes`, `navy`, `value_morale_rating`, `boarding_actions`, `linked_at_plot` or `BoardingAction` fields).

### State History
- Indexed by turn number: `environment_history[turn]`, `ship_history[ship_id][turn]`
- Snapshots saved AFTER turn completes, before advancing

### Environment RNG
- `EnvironmentController` manages RNG seed for determinism
- Wind changes use 2d10 rolls; a 16+ steps the wind one step back toward the scenario's starting speed and direction (`EnvironmentState.original_wind_speed` / `original_wind_direction`, set in `initialize_from_scenario`; direction the shorter way round)

### Movement Allowance Lookup
- All keys are **strings** (including wind_speed and rigging_quality)
- Wind-facing `"L"` (luffing/into wind) is a special case that always returns 0
- Uses `assert()` for parameter validation — fails fast on bad input
- **Blocked wind** (5.G) is applied on top of the table, never inside it: `BlockedWind` (`scripts/server/blocked_wind.gd`, pure statics) gives −1 MA (never to 0) when every hex directly to windward of the ship (two at WF=C/B, one at WF=R) is held by a ship at FS or above that is not dismasted. `ShipStateController.get_movement_allowance` uses the ships' positions; the movement validator uses the plotted position against the other ships' positions. `DataManager.get_movement_allowance` is the bare table.

### Planning Panel
- `scripts/ui/planning_phase_ui.gd` + `scenes/ui/planning_phase_ui.tscn` in the context panel; reworked from `prototypes/planning_panel/planning_panel.html` (changes C1–C8 listed there). Ship cards (`ShipListItem`) are an accordion: the selected card is expanded (title, Movement / Crew & damage, then `ShipCardStatus`: Hull, Rigging, Crew (per-section boxes labelled with each section's job: the only place the panel shows crew activity), Marines (caption says what they do), Guns (a row per broadside, a segment per gun factor, dismounted guns empty, sections-firing readout)); every other card is one row (`ShipHealthIcon`, name, badge, "Speed n/MA" (speed last turn over this turn's movement allowance), ✓ once orders are in). Selecting a card collapses the others; Movement is on the expanded card only. The box stays while plotting and the panel scrolls the plotting controls into view. There is no separate ship status window (removed with its card button and the map's "i" icon); an enemy's status is the plate on the water (`ShipStatusOverlay`) when it is clicked or hovered; the player's own ships get no plate (`GameController.shows_status_plate`), their card shows it all. Texts in `CrewOverlayText` (`critical_lines`, `crew_caption`, `section_job`, `marines_caption`, `gun_rows`, `guns_readout`).

Drag, click-then-click and right-click (or Shift+F10) assign; each assignment is sent at once with `player_plot_crew` and redrawn from the normalized plan.
- **Keys:** C = crew overlay; **Home** = centre the camera on all ships (was C).

### Known Limitations
- Moves ahead are not limited to the map bounds (a bow may be plotted off the map), but a turn whose stern would leave the map is refused; drift treats the map edge as blocked.
- The stub AI stalls instead of tacking when the wind blows straight against its approach.
- Not implemented: sinking, signalling (signal halyards cut blocks nothing), the optional rules (14), towing (the `towing` flag is read but never set). A prize does not grapple, ungrapple or unfoul (10.H.2 allows it). An exploded ship stays on the map as a wreck. Milestone 3 items (anchoring, lower-deck guns, chase guns, medium guns, class 4 ships) are also absent. Everything else of Milestone 2 is in: crew tasks (manual or Automatic), tacking crew, reorganizing, fire and explosions, repairs, marine fire, grappling, boarding, prizes, recapture and multi-ship boarding; `docs/rules/feature_diff.md` has the details.
