# CLAUDE.md

Guidance for Claude Code working on the Leeward project.

For human-facing developer setup (prerequisites, Godot MCP bridge, contribution flow), see `CONTRIBUTING.md`. This file is Claude-facing.

## Project Overview

Leeward is a Godot 4.6 naval sailing game (Age of Sail) using the Forward Plus renderer. It's a turn-based tactical game where players command ships on a hex grid, plotting movement and combat across a 10-phase turn cycle. Architecture is server-authoritative with a State-Controller-View pattern.

**Rules authority:** the game implements *Close Action* (1997). The rules are `docs/rules/close_action.md` (OCR of `docs/CoA_-_Close_Action_the_Age_of_Fighting_Sail_vol_1_1997.pdf`, with the charts as images in `docs/rules/images/`). Where Leeward differs from them, deliberately or not yet implemented, is tracked in `docs/rules/feature_diff.md`, which must be updated whenever a game feature is added or changed. Invoke the `close-action-rules` skill before building, testing or fixing game logic.

## Tooling (MCP Servers)

**Prefer the `godot-mcp` MCP server for Godot interactions whenever possible**, instead of ad-hoc shell commands. It is the most reliable way to drive the editor and a running game. Use it for:
- Running/stopping the project (`run_project`, `stop_project`) and reading output (`get_debug_output`).
- Checking the running game for problems: `game_get_errors` (push_error/push_warning + parser warnings) and `game_get_logs` (print output). After editing GDScript, relaunch and confirm `game_get_errors` returns zero — this is the canonical way to verify a clean build.
- Inspecting/driving the live game (scene tree, nodes, input, screenshots) via the `game_*` tools, and project/scene/script management (`read_scene`, `read_project_settings`, `list_project_files`, etc.).
- Note the in-game interaction server (`scripts/mcp_interaction_server.gd`) binds `127.0.0.1:9090`; the `game_*` tools connect to it. If `game_get_errors`/`game_get_logs` returns "No active Godot process" right after launch, it's a startup race — wait ~1s and retry.
- **Clicking the UI**: `game_click(x, y)` takes **window pixels**, not UI coordinates. Multiply a control's `get_global_rect()` position (or `Camera3D.unproject_position()` for a hex or ship) by the root viewport scale, `get_tree().root.get_final_transform().get_scale()` (about 1.89 on a Retina display), before clicking. Unscaled coordinates land on the wrong spot and look like ignored clicks. Drive the UI with real clicks rather than by emitting control signals.
- A script error inside `game_eval` freezes the running game; stop and relaunch it.

**For Godot API docs, use the `context7` MCP server with library `/godotengine/godot-docs`.** Call `context7` (`query-docs` against `/godotengine/godot-docs`) before relying on memory for engine/class/method APIs — training data may lag the 4.6 API. Skip the `resolve-library-id` step; this project's library ID is fixed.

Uses [GUT](https://github.com/bitwes/Gut) v9.5.0 (`addons/gut/`). Tests live in `test/unit/` and extend `GutTest`.

```bash
make test                         # Run all tests (headless)
make test-verbose                 # Run all tests with detailed output
make test-file F=test/unit/test_data_manager_ships.gd  # Run a single test file
```

Test naming: files prefixed `test_`, methods prefixed `test_`. Use `before_all()` / `before_each()` for setup.

## Architecture

### State-Controller-View (SCV)

- **State layer** (`scripts/state/`): `Ship` (immutable identity + type data), `ShipState` (mutable game state, references `Ship`), `EnvironmentState`. Serializable, deterministic. No logic. `TerrainMap` is the scenario's board (a pure, read-only query object built once from the scenario dictionary and cached by `TerrainMap.of`): rectangle bounds in odd-r offset, land, shallow areas (depth base + d6), typed boundaries (`open`, `none`, `escape`) and the `Terrain: …` validation `errors`.
- **Controller layer** (`scripts/server/`): Server-authoritative game logic. All state mutations happen here. Controllers check `is_server` before mutating. Clients are read-only.
- **View layer** (`scripts/view/`, `scripts/ui/`): Presentation only. Reads state, renders visuals. Never mutates game state.

### Autoload Singletons

- **GameState** (`scripts/autoload/game_state.gd`): Central state container. Holds all ships, environment, turn/phase, state history. Creates and owns all server controllers in `_ready()`.
- **DataManager** (`scripts/autoload/data_manager.gd`): Loads and caches JSON data (movement tables, ship definitions, scenarios). Provides lookup methods. `DataManager.combat_tables` is the `CombatTables` instance holding the 1997 combat charts.
- **Trace** (`scripts/autoload/trace.gd`): Lightweight tracing/logging autoload. **Required** in runtime code — `.claude/hooks/block_raw_print.py` blocks raw `print()` at Edit/Write time. Exempt: `scripts/util/`, `scripts/utils/`, `scripts/autoload/trace.gd`, `scripts/autoload/mcp_server.gd`, `addons/`. Per-line bypass: trailing `# allow-print`. Covered by `test_trace.gd`.

**Auto-test hook**: `.claude/hooks/run_related_tests.py` runs `make test` automatically after editing files in `scripts/server/`, `scripts/state/`, `scripts/core/`, `scripts/autoload/`, or `test/unit/`. Configured as a `PostToolUse` hook in `.claude/settings.json`.

Note: `scripts/autoload/mcp_server.gd` lives in this folder but is **not** an autoload — it's wired through the `godot_mcp` editor plugin.

### Turn Phase Cycle (10 phases)

SETUP → ENVIRONMENT → PLANNING → MOVEMENT_RESOLUTION → COMBAT_RESOLUTION → DRIFT_CALCULATION → STATUS_ADJUSTMENT → MORALE_CHECK → MESSAGE_DELIVERY → POST_COMBAT → END_TURN → (back to ENVIRONMENT)

Managed by `TurnPhaseController`. All phases do real work. The `GamePhase` enum is unchanged; combat's two steps are `TurnPhaseController.CombatStep` (`NONE`, `DECLARE`, `RESOLVE`).

- **ENVIRONMENT**: `EnvironmentController.tick_environment` (wind/sea rolls via `Dice`). 3.B.6: it first applies the change rolled last turn (`EnvironmentState.pending_wind_speed` / `pending_wind_direction`, −1 = none), then rolls next turn's change and stores it as pending (WIND event with `forecast: true`; the minimap shows it). When the wind rises from 0 it sets `EnvironmentState.calm_ended_turn` (`calm_just_ended(turn)`): no ship is in irons that g-t (3.D.4).  Before any wind change, `map_controller.place_arrivals(turn, phase)` puts every waiting reinforcement due on the map (ARRIVED at its entry footprint, facing and sail state, at `arrival_speed`: the movement allowance there as if it had sailed straight at it last turn; a held entry hex puts it back a turn, ARRIVAL_DELAYED).
- **PLANNING**: on entry `_open_talks()` (after the auto-ready step, before a possible advance) opens a talk (11.B.3) for each pair of on-map ships of one side, under different players, whose sterns touch and whose commanders are both human (AI captains do not talk, no die rolled): one d6 (1-3 `ship_a`'s commander speaks first, 4-6 `ship_b`'s), stored in `GameState.talks` (`{id, turn, ship_a, ship_b, first_player, second_player, messages}`, id `talk_<turn>_<a>_<b>`); `player_send_talk(player_id, talk_id, text)` takes one message of at most `SignalText.TALK_LIMIT` words per player, first then second, logging `TALK` at once (no `players_ready` check: a talk lapses with PLANNING; halyards cut do not stop it); `talks_for(player_id)` is the query (copies). Then on entry `boarding_controller.take_link_snapshot()` records the ships fouled or grappled to each ship (`GameState.linked_at_plot`, 10.A.2: only those may be boarded this g-t). AI ships plot (`StubAI.plot_all_ai_ships`, then `assign_crew`, which also sets each AI ship's boarding order); the player's ships get default courses stored on entry (`DefaultCourse`, 6.G.2; `phase_changed(PLANNING)` is emitted after they are stored), then the player edits courses on the map with `player_extend_course` / `player_cut_course` (always on, no Movement mode; `player_reset_course` restores one ship's course, `player_reset_planning` the whole turn from `planning_snapshot`), optional sail-change orders and (crew overlay) crew sections through `player_plot_crew` / `player_set_crew_auto`; readiness is per player (`players_ready`: player id → bool, one entry per `GameState.player_ids()`; read with `is_player_ready(id)`): `_auto_ready_players()` marks every AI player (`ai_player_ids`: every player `GameState.start_scenario` was not told is human; empty in headless tests, which submit for both) and every player commanding no ship in play (`in_play_ships_of_player` empty) ready as PLANNING begins, and again on each submit; the phase waits for `player_submit_plan(player_id)` from every other player (when everyone is ready at entry, planning ends at once, after `phase_changed(PLANNING)`). Every `player_*` request checks `GameState.commands(player_id, ship_id)` (the ship's `commander_id`; a ship with none, as in a game set up without a roster, is commanded by the player whose id is its side, `ShipState.commanding_player()`); `plan_errors(player_id)` covers that player's ships. Course and movement plotting requests are refused outside PLANNING (SETUP excepted, before any turn loop) and once the player's plan is in. When every player is ready, `crew_task_controller.finalize_plots()` makes each crew plot legal against the final movement plot before the phase advances.
- **MOVEMENT_RESOLUTION**: `CrewTaskController.begin_turn_tasks()` turns the crew plots into tasks (sail changes start; sections at the braces for a turn at MA 0 become a T task, which the Tacking roll reads: +2 per section short of 3, at most +6, 5.D.2a; a reverse tack, turning back the way the ship came into irons, adds +3, 5.D.3b, read from `ShipState.irons_entry_turn`; sets `plotted_sections`), then the movement resolver runs at proportional pace: step k of an N-step plot at time k/N (`MoveSchedule`); the segments are the distinct times (sets `moved_this_turn`, `mp_used_this_turn`). Waits for the view to call `on_playback_completed()`, which applies results and then calls `crew_task_controller.after_movement()` (a hull repair ends on a ship that moved more than 4 MPs, 8.F.3b). **Bearing off (6.D)** is the owner's decision: ships of players in `bear_off_prompt_player_ids` (player ids: `GameState.start_scenario` sets the human players, `[0]`; empty in headless tests; a ship is prompted when its commander is listed) stop the resolution at a potential collision — `run()` returns a log with `pending_bear_off` (a `MovementTypes.BearOffSituation`), the view plays it up to that segment and calls `on_playback_paused()`, which emits `bear_off_decision_requested(player_id, situation)` for the ship's commanding player; `player_submit_bear_off(player_id, ship_id, choice)` ("port"/"starboard"/"collide"; returns "" or a reason) re-runs the resolver with the answers so far (`_bear_off_decisions`, same RNG start, so the prefix repeats) and the new log has `resume_impulse` = that segment. Other ships decide by `StubAI.bear_off_choice` (always bears off when a turn is legal; never rams). Success amends the plot (turn, then ahead to the deceleration minimum) and replays like an overlap rollback; once per g-t. Potential collisions found on one segment are decided in a d10 order (6.D.3c: `_order_bear_offs`, logged as `BEAR_OFF_ORDER`, repeated on re-runs). Tests that want a plain collision pass `{ship_id: {"choice": "collide", "segment": n}}` as `run()`'s third argument. **Springs step (anchoring): right after `begin_turn_tasks`, `anchor_controller.resolve_spring_step` applies the spring turns (HS) and veering in (VI) begun this g-t, before any ship moves (13.D.2, 13.E.2; refused and logged `SPRING_TURN`/`VEER_IN` with `refused` when the hex is held, land or off the map; no dice).** A ship with an A task and MPs plotted has the anchoring erased at End Planning (13.C.1). An anchored ship cannot plot movement (`SHIP_ANCHORED`), and the resolver ignores any plot of an anchored or aground ship (`_get_plotted_steps`); she is never in irons (`IronsRules.excused`). **Towing (12.A.5–11):** a towed ship has no plot (`SHIP_TOWED`): on each step her tower makes she follows in her wake (`MovementResolver._follow_tows`, pose by `TowRules.follow_pose`: bow = the hex the tower's stern left, facing her tower's new stern; logged `TOW_FOLLOW` on the tower's segment, `ResolutionLog.towed_by`), takes the tower's speed and counts her follow steps as MPs. The tower's MA loses `TowRules.ma_loss` (12.A.7, `ShipStateController.tow_mp_loss`, floored at 0). When the follow is blocked (a third ship, the edge, land) the tower's step is undone with `TOW_HELD`, her plot trimmed with no deceleration padding and the resolution re-run (a rollback of kind `"tow"`, like an overlap rollback; contests by `_settle`); a tower stopped by a collision is rammed by her tow (`_apply_tow_collision`, 12.A.11: the tow's rigging-loss dice, then the fouling d10; not when the tow is already held on that segment; a slower tower is never rammed); a tow grounding parts the tow. A tow rollback that undoes a bear-off's turn keeps the BEARING_OFF_ROLL in the final log (`run()`, `undone_bear_offs`); `stop_cause` gives `collision` over `tow` when the held tower was run into, and `log_outcomes` reads the COLLISION `tow` flag (and its target, the tower) from the ram's event detail. Tow invariant: the towed ship's bow plus her facing is her tower's stern hex.
- **COMBAT_RESOLUTION**: first `boarding_controller.declare()` announces the boarders away (BA tasks begun this g-t; the defender's marines are replotted to FB, 10.C.3; a struck or undefended defender is captured at once, 10.E.2a–b; several ships boarding one each get an action and share out her defence, a sixth boarding ship takes her outright, 10.F.2). Fire declaration is a step inside this phase (targets are chosen after movement). If neither `gunnery_calculator.any_eligible_shot()` nor `marine_fire_resolver.any_eligible_marine_shot()` is true: with a boarding announced or an action in progress the phase goes straight to `RESOLVE` and fights the boarding alone (emits `combat_log_ready`), else it is skipped (`combat_step` stays `NONE`). Otherwise `DECLARE`: emits `fire_declaration_requested`, the AI submits via `StubAI.submit_fire_orders()`, the player via `player_submit_fire_orders(player_id, orders, marine_orders := [])` (marine orders are `{ship_id, target_id}`; returns "" or a rejection reason; orders are hidden until both are in). Then `RESOLVE`: `marine_fire_resolver.prepare()` captures the marine shots, `gunnery_resolver.resolve()` computes all shots against start-of-step state and applies damage, then `marine_fire_resolver.resolve()` rolls the marine shots (7.G.5: boxes at the start of the step; dice after all gunfire), then `boarding_controller.resolve()` fights every live boarding action one round (10.C.4; all rounds rolled first, results applied together, 10.F.3), emits `combat_log_ready`; waits for the view to call `on_combat_playback_completed()`.
- **MESSAGE_DELIVERY**: `_deliver_signals` marks this g-t's signals delivered (11.A.4), logs one `SIGNAL` event each in `from_player` order, emits `signals_delivered(turn)`, then advances. Signals (`SignalState`, `GameState.signals`) are sent in PLANNING with `player_send_signal(player_id, from_ship, address, text)` (checks in order: PLANNING and plan not submitted, the player commands the ship, ship not out of play or dismasted (11.B.2b), no in-play ship of the player with `signal_halyards_cut` (11.B.2c; struck ships and prizes never count: their crit is never fixed), a valid address (`{"kind": "fleet"|"group"|"ship", "name"}`, own side), `SignalText.words`, word count ≤ `SignalText.limit`); a new signal replaces the player's undelivered one; `player_cancel_signal`. Queries (copies, never live state): `signals_for(player_id, turn := -1)` (delivered, the whole side's), `pending_signal(player_id)`, `ships_addressed(signal)`. A sender struck after sending still delivers. Delivery also reads each signal as a standing order (`_apply_signal_orders`, `SignalOrders.parse`: ENGAGE, ENGAGE/ATTACK <ship>, CLOSE TO n (1-15), FOLLOW FLAGSHIP / <ship>, FORM LINE, DISENGAGE; the last order wins; an engage target must be an enemy, a follow leader a friend, FLAGSHIP resolves to the side's in-play fleet flagship) and sets it with `ShipStateController.set_standing_order` on every in-play, on-map addressed ship, human-commanded ones too (information only; a `line` order carries `group`). Read it with `GameState.order_of(ship_id)` (the stored `standing_order`, or `{"order":"engage"}` when none or its target/leader is out of play or off the map; `{}` for an unknown id); the stub AI steers by it (see `stub_ai`).
- **DRIFT_CALCULATION**: `drift_resolver.resolve()` for stopped ships; ships fouled or grappled together drift as one group (8.A.6: connected over `ShipState.linked_ids()`, one d10 by the member least likely to drift, no partial drift, any blocked hex holds the group).  An aground ship never drifts and holds its whole group (`_holds_group`); a drift onto land or into a too-shallow hex grounds the ship in place (`map_controller.ground`, AGROUND), one across a `none` edge loses it and one across a permitted escape edge escapes it (`MapRules.forced_move`). **Anchoring step (after drift, `anchor_controller.resolve_anchoring`):** SoP V.A, riding to the anchor (every ship anchored before this g-t, leeward first: swing one 60-degree step toward her proper facing, settle cable 0 to 1, ride round to a wind shift, a VO adds a hex, one forced move to the footprint `AnchorRules.footprint`; a blocker means a fouling roll and the ship holds, land grounds her, the edge and a fouled or grappled ship hold, logged `ANCHOR_MOVE`); then V.B by ship id, a live A drops the ready anchor (`ANCHORED`) and a live AX cuts the cable (`CABLE_CUT`). No riding at wind speed 0 (13.E.3). An anchored ship never drifts and a group with an anchored member holds (`DriftResolver._holds_group`, 8.A.6). A tower and her tow drift as one group (`ShipState.drift_group_ids()` = `linked_ids()` plus the tow partner; eligibility is the tower's `moved_this_turn`, one d10 by the member least likely to drift). After `resolve_anchoring` (SoP V.B) `tow_controller.resolve_cuts` cuts the tow of any ship with a live TX begun this g-t (TOW_CUT `tx`).
- **STATUS_ADJUSTMENT**: first grappling, then ungrappling (8.C, SoP V.C–D; `grappling_controller.resolve_grapples` / `resolve_ungrapples`). Each is a **maintenance-orders step** (`TurnPhaseController.MaintenanceStep` `GRAPPLE`, `UNGRAPPLE`), modelled on the bear-off pause: a player in `maintenance_prompt_player_ids` (player ids, set with the bear-off ids; empty in headless tests) who has a choice (`maintenance_options(player_id, step)`: an eligible grapple, or a grapple to cut, for the ships that player commands; friend or foe by `side`) is asked through `maintenance_orders_requested(player_id, step, options)`, and the phase waits (`advance_phase` is ignored) until `player_submit_maintenance_orders(player_id, {"grapple": [[ship, target], …]})` (or `{"ungrapple": …}`; returns "" or a reason; checks phase, waiting step, player, ship ownership and that each pair is one of the options). No choice, no pause. Every other player's ships are ordered by `StubAI.grapple_orders(player_ids)` / `ungrapple_orders(player_ids)` (and prize sizes by `StubAI.prize_sizes(player_ids)`). The ungrapple step comes after the grapple rolls, so the player may cut a grapple made the same g-t. Then `critical_hit_controller.resolve_fixes()` (8.D.5 fix rolls for lasting crit effects; sheets cut expires), then `fire_controller.resolve()` (the Fire & Explosions sub-phase, SoP V.F: firefighting, fire damage, growth and spread, explosion rolls, unfought-fire MCs), then `crew_task_controller.advance_tasks()` (crew tasks counted, completed or cancelled; repairs are recorded (8.F.5, `REPAIR` event), RO completes and sail changes complete here; FB completes into a BR task), then a third maintenance step, `MaintenanceStep.PRIZE` (10.G.6): a prompted captor whose boarders finished RO with more boxes than the minimum prize crew chooses its size (`maintenance_options` → `BoardingController.prize_size_options`; `player_submit_maintenance_orders(player_id, {"prize_size": {action_id: n}})`, minimum to the surviving boarders; an action not named keeps the minimum; the AI by `StubAI.prize_sizes`), then `boarding_controller.advance_reorganizing()` (the prize crew of a won action whose boarders finished RO goes aboard, 10.G.7). In the fire sub-phase a prize's fires are fought by her original crew below (10.H.3, `FIRE_FOUGHT` with `below`). Unfouling and ungrappling skip pairs locked in a boarding action (8.C.5, 8.D.4). **Tow attempts come first of all:** at the start of the phase, before the GRAPPLE step and its prompt, `tow_controller.resolve_tow_attempts` rolls (one d10 per tower, ship-id order, no prompt) every standing `crew_orders.tow` order `take:<id>`: the position (tower's stern in the hex ahead of the towed ship's bow, 12.A.4a) is checked then; the roll is the grapple roll with the towing −1 (`GrapplingController.grapple_chance(…, towing)`); TOW_BEGUN logged; success begins the tow (`begin`) and clears the order; a target that cannot be taken at all (unknown, own ship, enemy, struck, destroyed, escaped or off the map: `TowRules.take_target_error`) lapses the order (TOW_BEGUN with `lapsed`, no die). `GrapplingController.grapple_error` refuses the two ends of one tow and a target the ship rolled a TOW_BEGUN against this g-t, so neither is a maintenance option (no GRAPPLE pause for them).
- **MORALE_CHECK**: `morale_controller.resolve_checks()` rolls the checks noted during the turn; failures lower crew quality or strike the ship.
- **POST_COMBAT**: waits for End Turn (`player_end_turn(player_id)`, per player in `ended_turn`): accepted from a human player (`human_player_ids`, or player 0 when that is empty, as in headless tests) who commands a ship in play, and END_TURN begins once every such human has ended the turn; AI players and players commanding nothing in play are not waited on; when no human commands a ship in play, any human's End Turn ends it. `advance_phase()` is ignored here. No timer.
- **END_TURN**: `victory_controller.check(turn)` (agreement first, 2.A.1: when every side present has `GameState.end_offers[side]` true the result has reason "agreement", the winner the side with more points or −1; offers come from `TurnPhaseController.player_offer_end(player_id, offer)`, only from `GameState.senior_human_player(side)` = the human commanding the in-play fleet flagship, else a squadron flagship, else the lowest-id human, else −1; it logs `END_OFFER`; a side with no human never offers; cleared in `start_new_game`). A non-empty result is stored in `phase_controller.game_result`, `game_over` is emitted, and the loop stops (phase stays END_TURN, `advance_phase`/submits are refused). Otherwise `boarding_controller.end_of_turn(turn)` keeps the turn's actions in `GameState.boarding_history` and drops finished ones (a repulse is kept one g-t for counter-boarding), flags are cleared and the next turn begins; at its start `boarding_controller.start_of_turn()` retakes any prize whose prize crew is below the minimum against an original crew of at least twice its boxes (10.H.4, `RECAPTURED`). Exploded ships leave the map first (8.G.1f: `remove_from_map`, see Ship Status). A side with no ship in play (prizes do not count) is defeated; a side with no ship able to move or fight loses too (2.A.1).  Exploded ships leave the map first (8.G.1f), then `map_controller.resolve_escapes(turn, phase)` reports every declared ship (ESCAPE_DECLARED) and escapes those whose condition holds (V.D.1–3, `MapRules.condition`), before the victory check. Victory counts escaped, aground (default; `aground_counts_lost: false` scores them by sections destroyed) and waiting ships (`VictoryController`: any number of sides; with three or more the game ends when any one side is defeated or unable).

The gunnery and marine fire resolvers and the damage, critical-hit, drift, fouling, morale, crew-task (and its handlers: sail, fire, repair, boarding tasks), grappling and boarding controllers append typed events to `GameState.turn_log` (`PhaseEvents.PhaseLog`, made by `GameState.new_turn_log`, which stamps each event with the controlling side of every ship it names, `PhaseEvent.sides`; the combat log labels ships "(yours)"/"(enemy)" by that, so a later capture does not relabel earlier lines); the environment controller logs WIND, the movement resolver COLLISION, STOPPED_SHORT, IN_IRONS and TURN_UNDONE, and `TurnPhaseController` adds HOLD_FIRE (ships that could fire but did not) and the VICTORY event at END_TURN; planning logs no events; finished turns are kept in `GameState.turn_logs[turn]`. The UI renders these as the combat log.

When changing a phase method, invoke the `phase-implementer` skill (`.claude/skills/phase-implementer/`). It codifies the SCV pattern (server-authority guard, `game_state.dice`, automatic state-history snapshots, GUT test template).

### Server Objects on GameState (created in `_initialize_server_controllers()`)

All except `dice` (takes the RNG) and `fire_geometry` (takes a `HexGrid`) take `game_state` in `_init` and reach collaborators through it. Names are exact. A game is started with `GameState.start_scenario(scenario, human_player_ids)` (server only): it builds the scenario's ships (type, navy), sets the prompt and AI player ids, then `start_new_game`; the view makes its ship views on `game_started`.

- `dice` (`Dice`): the default source of randomness for game logic (see Dice below).
- `fire_geometry` (`FireGeometry`, `scripts/core/`): pure geometry — `bearing_side` (which broadside covers a hex from a battery hex, or -1), `range_between` (closest hexes), `battery_bears`/`in_battery_arc` (per-battery arc and LOS), `rake_type_ships`, `has_line_of_sight`, `blocking_hexes` (friendly blocking hexes per battery, 7.B.10–12; `GunneryCalculator.preview` and `StubAI._score_position` pass them to `battery_bears`), `broadside_hexes` (per battery hex; callers draw bow ∪ stern).
- `gunnery_calculator` (`GunneryCalculator`): pure queries, no dice, no mutation (declaration rules delegated to the static `FireRules`) — `preview(order, two_targets)` gives a `ShotPreview` (modified gunfire number + modifier breakdown), `eligible_shots` (broadsides and chasers), `any_eligible_shot`, `validate_orders`. Types in `gunnery_types.gd` (`FireOrder`, `ShotPreview`; aims `low`/`high`, ammo `round`/`dismantling`).
- `gunnery_resolver` (`GunneryResolver`): rolls and applies a set of `FireOrder`s simultaneously, logging each shot.
- `marine_fire_resolver` (`MarineFireResolver`, 7.G): pure queries `preview(ship_id, target_id)` (boxes, column, DRMs, `hit_max`, `chance`), `eligible_marine_shots`, `any_eligible_marine_shot`, `validate_orders(player_id, orders)` (eligibility in `FireRules.marine_error` / `marine_orders_error`); `prepare(orders)` then `resolve(shots, phase)` roll one d6 per firer in ship_id order and apply the boxes through `DamageController.apply_crew_losses` (Crew Loss "All Other Causes", no roll when the target has one crew type). Logs MARINE_FIRE, then DAMAGE with cause `marine_fire`. The boarders −1 reads live FB/BR/BA tasks (`has_boarders`); the grappled-or-fouled DRM reads `linked_ids()`.
- `damage_controller` (`DamageController`): applies rigging/hull/crew boxes (lowest section first), dismounts guns on hull-section loss, notes morale checks, strikes ships. Every DAMAGE event's data carries `sections_emptied: {"rigging": [i…], "hull": [i…], "crew": [i…]}` (the section indices that event emptied; crew 4 = the marines), which `PlayerView` reads.
- `critical_hit_controller` (`CriticalHitController`): critical hits (7.D.7–12) — the gunfire crit roll (natural 6, then CH d6 + `ch_modifier` ≤ CH#), the Rigging/Hull Crit tables by aim, a FIFO queue of rigging/hull checks for emptied sections (`DamageController` queues them; `drain` chains 7.D.12), lasting effects in `ShipState.critical_effects` (read via `ShipState` helpers: `obscured_penalty`, `critical_mp_loss`, `max_turns_per_gt`, …), hull #10 fire roll (d10 + SK ≥ 6) and hull #12 afire through `fire_controller.start_fire`, a hull #12 explosion through `fire_controller.explode` (DESTROYED, then blast and debris), hull #4 crew disorganized (`_disorganize`: the highest sailor section not already disorganized is forced onto RO via `crew_task_controller.force_task`), rigging #3 `signal_halyards_cut` (fixable; while it lasts no ship of that player can send a signal, 11.B.2c, checked in `player_send_signal`), and `resolve_fixes` (8.D.5) in STATUS_ADJUSTMENT. Tables in `data/rules/critical_hits_table.json` and `poor_maneuvering_table.json`.
- `fire_controller` (`FireController`, `scripts/server/fire_controller.gd`): fires and explosions (8.E, 9.B.1c–d) and the FF crew-task handler (registered as `FF`). `start_fire(ship_id, cause, phase, source_id, in_fire_subphase, extra)` (adds a `ShipState.fire_list` entry; its fear MC, trigger `fire_<seq>`, none when struck; a section on fire watch, FF with fire −1, is attached at once), `resolve(phase)` (dice order in the code: firefighting d10s, then 1H+1R per fire burning since this g-t or earlier, then growth (every 5 g-t's) and spread (d10 ≤ 4 + SK of the fouled ship), then 2d6 explosion rolls for burning ships with no hull boxes (≤ 2 + `explosion_checks`), then an MC per fire that existed at plotting with no FF task), `explode(ship_id, phase)` (destroy, then blast at range 1–2 from `fire_table.json` as the MGN on the firing-high column, then flaming debris d6 ≥ range within 6, fouled ships always), `skill(ship)` (CQ G once struck). Fires made in the Combat Phase burn that g-t; fires made in the sub-phase burn from the next. Readings: better crews resist fire (spec §9 Q1). A struck ship fights its fires (automatic allocation, CQ G, no MCs); `DamageController.strike` ends its other tasks. Developer UI: `dev_commands.start_fire(ship_id)`.
- `repair_controller` (`RepairController`, `scripts/server/repair_controller.gd`): the RR, RH and RS crew-task handler (one instance registered for all three; 8.F, 9.B.2). Statics used by `CrewRules`/`CrewAuto`/the overlay: `refusal(ship, code)` (8.F.3: something to repair at plot time; RR only at FS, furled or dismasted, 8.F.3a; struck ships make none), `mp_warning(code, ctx)` (RH with more than 4 MPs plotted), `is_repair`, `max_mp`. Handler: `cancel_reason` (nothing left, or RH after > 4 MPs: `after_movement_reason`), `counts_turn` (not the g-t of an 8.F.6 reset, `reset_turn`), `on_complete` (`ShipStateController.repair_box(ship_id, kind)` → the section taking damage, or the one before it when full, section 4 when dismasted; RS removes the oldest `shrouds_severed`; logs `REPAIR`). `DamageController` sets `ShipState.checked_sections` the first time a section empties, and a section emptied again queues no Rigging/Hull Check and (hull) dismounts no guns (8.F.5, 9.B.2); `DamageController.rigging_hit_while_dismasted` (from `apply_hits`, gunfire and blast) calls `crew_task_controller.reset_progress(ship_id, "RR", …)` (8.F.6). Developer UI: `dev_commands.damage_ship(ship_id, rigging, hull)`.

else ten times the bow's distance to the nearest permitted escape boundary is taken off, and `ESCAPE_LUFF_PENALTY` hexes more for a heading at WF L; with no permitted escape boundary it scores as disengage; `hold_turns` makes a turn only when it scores strictly better than the present heading, so spare MPs are never spent turning into irons). `refusals` lists the submissions refused in the last `plot_all_ai_ships` (diagnostics). It submits fire orders (best modified number per broadside, a split side when no full broadside bears, at most two targets; low inside range 10; a ship ordered to engage a ship fires at her first when a battery bears; it fires its chasers only when no broadside bears, the same choice over the bow and stern chasers) and marine fire orders (`choose_marine_orders`: the adjacent enemy with the lowest DRM total, ties to one with boarders, then the lower ship_id; never a shot that cannot hit). After a successful submit it casts the lead (`_maybe_cast_lead`, through `player_set_cast_lead`) when the course is at most 2 steps and a step ahead enters a hex where the bow may or will ground. The `escape` posture (`_escape_posture`: the scenario's `ai: {side: "escape"}`, or a disengage order, when the side may escape this turn) declares escape (`player_declare_escape`) before plotting, then plots with the `escape` strategy. Anchoring (`anchor_order`, one of `AnchorRules.ORDERS`, put in `crew_orders.anchor`): an anchored ship prepares springs and hauls on them (`haul_choice`: the spring turn that brings most batteries of a side to bear on her target) and cuts only on a signalled CUT CABLES, under the escape posture, or on a signalled move order with no enemy in gun range, never while she could not make way or her lee is dangerous (`downwind_danger`); an unanchored ship anchors (`wants_to_anchor`) on an ANCHOR order or in an emergency (`drift_danger`: becalmed or dismasted with land or a `none` edge downwind), where the scenario allows. `SignalOrders` reads ANCHOR and CUT CABLES / CUT CABLE. Towing: `tow_order(ship)` (the tow crew order: "cut" for a tower with an enemy within `TOW_CUT_RANGE` 3 or with no way at any heading in a wind, else `take:<id>` for `tow_target`), `tow_target(ship)` (a dismasted ship or a prize of her side, claimed nearest first, one tower per candidate; only while no enemy is within `TOW_SAFE_RANGE` 8; a pair given up after `TOW_GIVE_UP_TURNS` 6 g-t's without getting closer is never tried again, `_tow_given_up`, cleared with a new game); the "tow" strategy steers to the tow station by a no-luff search, at most 2 MPs a g-t (`_steer`'s `max_moves`), wearing rather than lying in irons; a tow target wins over an ANCHOR order.
- `turn_log` / `turn_logs`: current and past `PhaseEvents.PhaseLog` (events: FIRE, HOLD_FIRE, DAMAGE, GUNS_DISMOUNTED, MORALE_NOTED, MORALE_CHECK, STRIKE, DRIFT, FOULED, UNFOUL, SAIL_CHANGE, CREW_TASK, VICTORY, COLLISION, STOPPED_SHORT, IN_IRONS, WIND, TURN_UNDONE, FIRE_STARTED, FIRE_FOUGHT, FIRE_UNFOUGHT, FIRE_SPREAD, EXPLOSION_CHECK, BLAST, DEBRIS, DESTROYED, MARINE_FIRE, GRAPPLE, UNGRAPPLE, BOARDERS, BOARDERS_AWAY, MARINES_DEFEND, BOARDING_ROUND, BOARDING_RESULT, SIGNAL, TALK, END_OFFER, SHIP_CAPTURED, PRIZE_CREW, RECAPTURED, REORGANIZING_ABORTED, DEFENCE_SPLIT, AGROUND, LEAD_CAST, ESCAPE_DECLARED, ESCAPED, ARRIVED, ARRIVAL_DELAYED the anchoring events ANCHORED, ANCHOR_MOVE, CABLE_CUT, SPRING_TURN and VEER_IN, and the critical-hit events; see `PhaseEvents.Type`). TOW_BEGUN, TOW_CUT are the tow events (movement resolution adds TOW_FOLLOW and TOW_HELD).

### Dice

`Dice` (`scripts/server/dice.gd`) wraps `GameState.rng`: `d6()` is 1–6, `d10()` is **0–9** (as on the 1997 charts), `two_d6()`, `two_d10()` is **0–18**. **New game logic must roll through `game_state.dice`** — never call `randi()` or `rng` directly. Known, accepted exception: `MovementResolver` still rolls directly from its `rng` property (`rng.randi_range`/`rng.randf`; it uses `game_state.rng` unless an explicit RNG is set), and `EnvironmentController` still passes `game_state.rng` into `_update_weather`. The 6.D.3c bear-off order roll is also a d10 from the resolver's `rng`, so it repeats when the resolution is re-run; so are the map dice of movement: the shallow-hex depth d6 (`_roll_depth`, 13.G.2a), the Poor Maneuvering d10 of a ship casting the lead (`_cast_lead`, 13.G.4b) and the aground rigging dice (6.E.3). Drift's depth d6 for a hex in a shallow area comes from `game_state.dice` (`DriftResolver`). `ScriptedDice` (`test/unit/scripted_dice.gd`, a `Dice` subclass) returns queued values (`queue([...])`; `two_*` pop two) so tests can fix rolls.

### Movement Plotting Protocol

Two paths write `ShipState.plotted_actions`:
- **Player (always-on course editing):** `TurnPhaseController.player_extend_course(player_id, ship_id, hex)` and `player_cut_course(player_id, ship_id, step_index)` (return "" or a reason; PLANNING, ownership, plan not submitted, ship able to plot) edit the stored course through the validator. A ship nobody plotted gets its default course (`DefaultCourse`, 6.G.2: continue at last turn's speed; `movement_plotted` false means the resolver rebuilds it; `DefaultCourse.for_ship` stores it at PLANNING start for human ships that can plot, and `stored_course` reads it; it is empty for a jammed rudder whose straight course would break 6.F). Read-only queries: `course_options(ship_id)` (path, `valid_next`, `remaining_ma`, `mp_used`, `max_ma`, `start_max_ma`, `is_tacking_attempt`, `rudder_error`), `start_of_turn_course`, `human_player_ids`. End Planning is always accepted: the resolver holds a ship whose stored course breaks a jammed rudder (`MovementValidator.rudder_jam_error`), the card shows `rudder_error` while editing. `player_reset_course` / `player_reset_planning` restore the start-of-turn course(s).
- **StubAI:** session-based async system in `MovementPlottingController`/`MovementPlottingSession`: requests START_PLOTTING, SELECT_HEX, UNDO, SUBMIT_MOVEMENT, CANCEL_PLOTTING; typed responses in `movement_types.gd` (PlottingStartedResponse, HexSelectedResponse, etc.); the version number increments on each change for conflict resolution. The player's view no longer uses sessions (`MovementPlottingClient` is gone).
- Valid moves stored in `ShipState.plotted_actions`
- A stopped ship (MA 0) whose first step is a turn plots nothing more (5.E.8).
- **Deceleration limit (5.E.4, 5.E.9):** a stored course must use at least last speed − deceleration MPs (`MovementValidator.deceleration_shortfall` / `deceleration_error`; 0 when the plot ends with no MPs usable at its heading: allowance used up, head to wind, a turn at MA 0). The allowance is never raised to the limit. Cutting a course short is allowed while editing; `player_submit_plan` refuses (returns false) while `plan_errors(player_id)` names a short course, and `course_options` carries `speed_error` for the card. Plotting sessions refuse it too (`TOO_SLOW`, `can_submit`); `StubAI._meet_deceleration_minimum` carries a short AI course on ahead. A ship with no course stored (`movement_plotted` false) sails its default course and is not checked. A ship in a collision ends the g-t stopped (speed 0, 5.E.3b). `stored_course` infers a missing step `move_type` from the hex and facing.

**Proportional movement (`scripts/server/move_schedule.gd`, pure).** Times are reduced `Vector2i`s (numerator, denominator), compared by cross-multiplication, never as floats. The schedule comes from the post-PM plots, built once per `run()`. Amended steps (bear-off, overlap rollback, lost stern contest) take the ship's next times, then trailing segments at times 2, 3, …. MA-0 turns happen at time 1, their Tacking roll before the first segment. The movement log has `segment_times`, `plot_steps`, `longest_plot` and `ResolutionEvent.time` (`MoveSchedule.START` for pre-movement events, `END` for the end check); `impulse` is the segment index. Playback (`MovementResolutionPlaybackController`) puts every ship on one clock of `longest_plot` units, each ship gliding at its own pace; it eases in on a ship's first glide and out on its last, linear between.

## Key Data Formats

### Movement Allowance Table (`data/rules/movement_allowance.json`)

5-level nested lookup: `speed_type → wind_facing → wind_speed → rigging_quality → sail_state → MA`

- Speed types: `L/F`, `L/S`, `L/VS`, `F/F`, `F/S`, `F/VS`, `C/F`, `C/S`, `C/VS`
- Wind facings: `C` (close-hauled), `B` (broad reach), `R` (reach), `L` (luffing — always returns 0)
- Wind speed: `1`–`4` (string keys). Wind speed 0 (calm) is not in the table: `ShipStateController.get_movement_allowance` and `MovementValidator._lookup_ma` return 0 before the lookup.
- Rigging level: `1`–`4` = number of rigging sections that still have boxes (see Rigging level rule)
- Sail states: `fs` (fighting), `ms` (maneuvering), `ps` (plain), `ns` (no sail)

Access via `DataManager.get_movement_allowance(speed_type: String, wind_speed: int, wind_facing: String, sail_state: String, rigging_quality: int)`. Note the argument order does **not** match the JSON nesting order, and `wind_speed`/`rigging_quality` are `int` at the API even though the JSON keys are strings. The `rigging_quality` argument is the **rigging level** (1–4, asserted); level 0 (dismasted) must never reach the table — `ShipStateController.get_movement_allowance` returns 0 first. Callers pass `ShipState.movement_sail_state()`, not the raw `sail_state`.

**Rigging level rule** (Close Action 5.F): rigging level = number of rigging sections with at least one box (`ShipState.rigging_level()`, 0–4). Plain sail (PS) only at level 4; manoeuvring sail (MS) at levels 4–3; fighting sail (FS) until dismasted (level 0). `max_sail_state()` gives the cap; `movement_sail_state()` = lower of carried `sail_state` and the cap. A ship carrying more sail than its rigging allows is not forced down: it moves at the capped state but takes damage at the state it carries. Low-level rows in `movement_allowance.json` are keyed `fs` accordingly.

Validate after edits: `python3 .claude/skills/validate-rule-table/scripts/validate.py`. Catches typos (e.g. `"FS"` vs `"fs"`) that would silently return 0 at lookup time instead of erroring.

## Conventions and Gotchas

### Hex Grid
- **The board is a rectangle** (`map_bounds` width × height, odd-r offset rows, centred on the origin: `TerrainMap.rect_hexes`, `axial_to_offset`, `offset_to_axial`, `in_bounds`), with four typed edges and optional inner boundaries (`TerrainMap.crossing(from, to)` gives the `Boundary` a step crosses). `open` is a wall (plots stop, drift is held), `none` loses a ship that leaves (no sea room), `escape` lets a declared ship of a permitted side leave; inner boundaries are `open` only for now. Land blocks movement and line of sight; shallow hexes have depth `base + d6` against the ship's `draft`. `Occupancy.in_bounds` and the movement validator read the same `TerrainMap`.
- **Axial coordinates** (q, r) with **pointy-top** orientation
- **Direction numbering**: 0=E, 1=SE, 2=SW, 3=W, 4=NW, 5=NE
- **World/screen orientation**: world +X is east, −Z is north. `IsometricCamera` builds a right-handed basis (covered by `test_isometric_camera.gd`); `camera_rotation_y = 90` is north-up/east-right and only the player's camera controls change it. Selecting a ship never rotates or zooms the camera (`pan_to_if_needed` pans only when the ship is near the screen edge).
- **Owner colours**: green = human player's ships, red = enemy (`ShipView.owner_color`, shared by the map ring/pennant and the minimap).
- **All ships are 2-hex** (`ShipState.get_ship_size()` = 2). `ShipState.hex_position` is the **bow**; the stern is derived, never stored: `HexGrid.stern_of(bow, facing)` = neighbour in `(facing + 3) % 6`, or `ShipState.stern_hex()` / `occupied_hexes()` (`[bow, stern]`). A ship always sits on two hexes, never along a hex spine (5.A.2c). Position the model with `HexGrid.ship_center_world(bow, facing)`, not `axial_to_world()`. (`HexGrid.axial_to_edge_world()` is live — `ShipIndicatorModel` uses it to compute hex-face midpoints for the selection indicators.)
- **Occupancy** (`scripts/server/occupancy.gd`, `Occupancy`): `build(ships, exclude_ids)` and `from_positions(bows, facings, exclude_ids)` map every occupied hex to a ship id; `overlapping_ids`; `in_bounds(hex, scenario)` (both hexes must be on the map). `GameState.placement_errors()` checks scenario placements. `GameController.ship_at_hex(hex, ships)` (static) picks a ship by either hex.
- **Turns pivot on the bow**: the stern swings. A plot step's `hex` is the resulting bow (unchanged for a turn, new facing); `ValidMove.hex` is the click target (for a turn, the bow's neighbour in the new facing). A turn whose new stern is out of bounds is refused. In resolution each step enters one hex (ahead → new bow, turn → new stern); a stern may swing into a hex another ship holds or a bow enters (`OVERLAP`, 6.B.2) if the two ships no longer share a hex at the end of the next segment on which the turning ship or any ship it overlaps moves; otherwise the turn is rolled back (`OVERLAP_ROLLBACK`, "already occupied" or "bow precedence"): the turning ship's plot is amended to the steps before the turn plus any ahead steps its deceleration minimum needs, and the whole resolution is re-run from the same RNG state. Two sterns swinging into one hex with no further MPs plotted (6.C.1b), or two ships swinging onto each other's bows (complete overlap, 6.B.5), contest it with the 6.C.2 roll (`CONTESTED_HEX_ROLL`): the winner turns (stub: the winner always chooses itself), the loser's turn is cancelled (`STERN_BLOCKED` "lost stern contest to <id>", stop cause `stern_contest`), never a collision; a loser that must still meet its deceleration minimum has its plot amended with ahead steps and the resolution replayed, with the rolls put back into the final log. If either stern ship has further MPs it is a 6.B overlap instead ("sterns together" if not cleared). A ring of ships each entering another's old stern lets the lowest-id group go first, assuming the ship ahead leaves; if a ring member turns out to be stopped, the pass is re-run with the ring broken (its old stern held), as for overlap rollbacks. A replay reuses each stern contest's first winner and rolls rather than rolling again.
- **Speed** counts executed steps, turns included, if the ship moved ahead at least once, else 0 (and 0 after a collision, 5.E.3b); `moved_this_turn` means moved ahead at least once (5.E.2).

### Sides, Arcs and Rake
- Side indices: `ShipState.PORT = 0`, `ShipState.STARBOARD = 1`. Starboard is `facing + 1` / `facing + 2`; port is `facing − 1` / `facing − 2` (mod 6).
- **Batteries**: each side has two batteries, one at the bow hex and one at the stern hex. **Broadside arc** (per battery): the 60° wedge centred on the beam out to range 15. `FireGeometry.bearing_side` is an angle test (60°–120° off the bow, with a 0.5° tolerance), which corresponds to the hex rows of directions `facing ± 1` and `facing ± 2`. Ahead/astern are blind to a broadside (the chasers cover them, below). A battery bears if at least one target hex is in its arc and every target hex in its arc has line of sight (target hexes outside the arc are ignored, 7.B.6); the ship's own hexes and the target's do not block. Range is measured to the closest hexes (7.C.4).
- **Battery orders** (7.B.1): `FireOrder.battery` is `full` (both batteries of the side must bear), `bow` or `stern`. A single battery is a half broadside: `half_broadside` (−8), except when the ship names two targets (only the −12 two-target modifier applies, 7.C.12g). `validate_orders` refuses a battery fired twice, more than two targets per ship, and bow+stern of one side at one target (declare a full broadside). A side may split (bow at one target, stern at another).
- **Chasers** (house rule, register §5, U; spec §4.3): each ship has a bow chaser and a stern chaser of one long-gun factor each (`FireRules.CHASE_GUN_FACTORS`, not part of `gun_factors`). They are two more "sides" of a `FireOrder`: `FireGeometry.ARC_AHEAD` / `ARC_ASTERN` (2, 3) = `GunneryTypes.CHASE_BOW` / `CHASE_STERN`, battery `GunneryTypes.BATTERY_CHASE` ("chase"; `FireRules.chase_mismatch` refuses a chase side with a broadside battery and the reverse). `FireGeometry.chase_arc(from_hex, facing, to_hex)` is the arc (±30° of the keel line from the bow hex ahead or the stern hex astern, to range 15; `chase_battery_hex` gives the hex); line of sight as for a broadside. TGF 1 has no BGN beyond range 7 on the chart, so a chaser reaches 7 (the chart wins). Round shot only (`make_order`). Applies: crew quality, sections firing, the two-target modifier (a chaser is one of the ≤ 2 targets, `MAX_TARGETS`), plain sail, WS 4, anchored, dismasted, voluntary reduction. Does not apply: initial broadside, rake (geometry unchanged: no bonus, no doubled crew hits, no raked MC), half broadside, broadside obscured, lower-deck guns, guns dismounted (a chaser is never dismounted); not counted for "able to fight" (2.A.1). `eligible_shots` lists chase shots after the broadsides (the order of its loop; `battery_rank` is the declaration and AI preference). The fire panel adds a "Bow chaser" / "Stern chaser" row per chaser that bears (`BroadsideColors.CHASE`, one blue for both; the map shows the chase arc via `GameController.battery_arc`), the ship card's Guns rows end with "Bow chase" / "Stern chase" (`CrewOverlayText.gun_rows`), and `PhaseEvents` FIRE events carry `side` 2 or 3 and `battery` "chase".
- **Previews**: `GunneryCalculator.preview_orders(orders)` previews a whole order set as it will resolve (two targets per ship; the initial-broadside bonus once per broadside, 7.C.10: the larger bonus, bow on a tie). The resolver and the fire panel both use it, so displayed numbers equal rolled ones; single `preview()` cannot know the rest of the set.
- **Fire rules live in `FireRules`** (`scripts/server/fire_rules.gd`, pure statics): target cap (`MAX_TARGETS`, `limit_targets`), bow+stern at one target = full broadside (`side_shots`), full before half (`battery_rank`), forced high aim and dismantling range (`make_order`, `effective_aim`/`effective_ammo`), and `declaration_error` (used by `validate_orders`). The calculator, the stub AI and the fire panel all call it; do not re-encode these rules elsewhere.
- **Fire panel** (`fire_declaration_panel.gd`, widget state and text only): one row per battery that bears on a target ("Full broadside" only when both bear, plus "Bow battery"/"Stern battery"), so a side can split between two targets or fire a half broadside at a target both batteries cover. The map highlights the chosen battery's arc (`GameController.battery_arc`). The no-shot reason comes from the bearing battery's preview. A "Marines" block per own ship whose marines may fire (7.G) lists each adjacent enemy with the Marine Fire column and the chance of a hit (`MarineFireResolver.preview`), plus "Hold musket fire"; the best shot is chosen by default. A ship with only a marine shot is listed too, so the panel opens. `GameController` reads `get_marine_orders()` and sends them with the gun orders in `player_submit_fire_orders`.
- **Rake** (`rake_type_ships`, 7.E.2): range (closest hexes) ≤ 5 and the firer is outside all four of the target's battery arcs, or directly ahead of its bow / astern of its stern and adjacent. Stern rake (firer aft of the target's beam line) doubles crew hits.
- Fire orders: per battery one target, aim `low`/`high`, ammo `round` (range 15) or `dismantling` (range 7). Ranges 10–15 are high only. Two targets = −12 on each shot. `FireOrder.mgn_reduction` (7.C.14) lowers the MGN by any amount, shown as the "Voluntary reduction" modifier; the fire panel has a stepper per row (`set_reduction`).

### Ship Status
- A STRUCK ship cannot move, fire, change sail, grapple, ungrapple or unfoul (a prize with her prize crew aboard may grapple, ungrapple and unfoul, 10.H.2: `ShipState.can_handle_lines()`) and is not a valid target, but it still drifts and blocks line of sight and hexes. It may be boarded and is then captured without a fight (10.A.3).
- **Towing** (12.A): a towed ship is IN TOW (plotting refused `SHIP_TOWED`; never in irons, 5.D.7; she follows her tower, takes her speed and never escapes alone, she escapes only with her tower, and a prize carried off the map stays CAPTURED); a tower is TOWING, and a tower whose tow is fouled or grappled cannot plot (`TOW_HELD`, `DefaultCourse.can_move`); the card's `PlanningSailUi.can_plot_movement` / `movement_block_reason` still read a tower's own dismasted / fouled / grappled lock under the TOWING badge. Both badges are on the ship cards; the map draws the hawser (`TowLines`: `refresh` from the hexes on every sync, `follow_views` every frame from the views' poses, so it rides the ships through playback) and the follower glides in her tower's wake. A tower does not escape while her tow is fouled, grappled or in a boarding action (`MapController.resolve_escapes`). Anchored ships neither tow nor are towed and a ship in a tow cannot anchor; a dismasted ship cannot tow; own struck ships are not towed; a tow parts when either ship strikes, is destroyed, is captured or grounds, when the tower is dismasted (ruling), and on hull critical #6 (d6, a 1). A rake of a dismasted ship in tow takes no MC unless her tower is dismasted too (9.B.1b).
- A CAPTURED ship (a prize, 10.H; `ShipState.is_captured()`) is under its captor's side: `ShipState.side` follows `controller_side` (−1 = the owner; `original_side` is the owner; `Ship.side` is the owner side, read from a scenario's `"side"` or the older `"player_id"`), and `GameState.ships_by_side` is re-indexed by `GameState.transfer_control`. It is out of play (cannot move, `SHIP_CAPTURED`, or fire, §8 Q2) but `is_targetable()` for its old side (10.H.1); `is_targetable()` = active or captured is the gunfire and marine-fire target test. Its live crew is the prize crew (empty until it goes aboard); `prize` holds `captor_id`, `original_crew`, `original_navy`, `prize_crew_aboard`, `fires_below`. With her prize crew aboard (`has_prize_crew()`, `crew_can_act()`) she plots only boarding and repairs (10.H.2; `CrewRules.normalize`, the overlay shows the guns idle and fires "fought by the original crew") and may be boarded (`can_be_boarded()`). Victory points go by original owner (`GameState.get_original_side_ships`); boxes detached as prize crew (`ShipState.detached_boxes`) are not destroyed sections. The map shows a prize flag and a "PRIZE · reorganizing n/m" label placed clear of the hulls (above the ship on screen, below or farther out when other ships are in the way; `ShipView.prize_label_place`); the minimap icon is hollow; the overlay's Guns readout says "Guns silent · a prize".
- A DESTROYED ship (an explosion: hull critical #12 or a burning hulk, `FireController.explode` → `DamageController.destroy`) is out of play like a struck one and counts as lost for victory, but it never drifts, fouls (its partner is freed when it blows up), burns (its fires are cleared) or takes damage; until the end of the g-t both its hexes still block movement, drift, line of sight and wind. At END_TURN (before the victory check, 8.G.1f) `ShipStateController.remove_from_map` takes every destroyed ship off the map (`ShipState.removed_from_map`, read with `is_on_map()`): it stays in `GameState.ships` (logs, history, victory) but map queries skip it — `Occupancy.build`, `BlockedWind.is_blocked`, `GunneryCalculator.friendly_ships` filter it, and the movement resolver, drift, the crew overlay inset and new ship views use `GameState.ships_on_map()`; use that helper rather than re-filtering. `ShipState.is_out_of_play()` = not active (struck, destroyed or captured) — use it for "cannot act / not a target / lost" checks, and `is_struck()` only where a wreck must differ (drift). `ShipView` shows a procedural wreck, and fades it out and frees itself once the ship is off the map (`GameController._sync_all_views` drops it from `ship_views`); the minimap icon goes grey, then disappears.
- An ESCAPED ship (`Status.ESCAPED`, after crossing a permitted escape edge or meeting the V.D conditions) is out of play and off the map like a removed wreck, scores its side the scenario's escape share and still yields its destroyed sections (VI.B.6). An AGROUND ship (`ShipState.aground`, `aground_turn`; `is_aground()`) stays in play, targetable and boardable, but cannot move, fire guns, drift or plot, and holds any fouled or grappled group; it scores as lost unless `aground_counts_lost` is false. A reinforcement waiting to arrive (`awaiting_arrival`, `arrives_turn`) is off the map and `is_out_of_play()` is true until `place_arrivals` enters it; it keeps its side alive and yields no points. `escape_declared` is the player's standing escape declaration (`player_declare_escape`; withdrawn with `false`), hidden from the other side by `PlayerView`; `plotted_actions.cast_lead` is the order to cast the lead (`player_set_cast_lead`).
- An ANCHORED ship (`ShipState.is_anchored()`; `anchor` non-empty, no status of its own) cannot plot or move (`SHIP_ANCHORED`), never drifts (it rides to her anchor in DRIFT_CALCULATION), is never in irons (`IronsRules.excused`, and not in the g-t after she cuts) and fires with +1 (7.C.12c, modifier `anchored`, kept the g-t she cuts; `GunneryCalculator.preview`). The map draws the anchor and cable (`AnchorMarkers`, view) and the card carries the ANCHORED badge.
- A fouled ship (`fouled_with != ""`) cannot plot or execute movement (plotting returns `SHIP_FOULED`); it can still fire and be fired on. A grappled ship likewise (`SHIP_GRAPPLED`, 8.C.7); the map draws its grapples (`GrappleLines`, view) and its card carries the GRAPPLED badge. A destroyed ship drops its grapples. Dismasted and struck ships also refuse plots (`SHIP_DISMASTED`, `SHIP_STRUCK`).
- A `ShipState` whose `rigging_current_hp` is all zeros is **dismasted** (level 0, movement allowance 0). Test fixtures must set rigging explicitly.

### Tests and RNG

### Server Authority
- All mutations guard with `if not is_server: push_error()` — never bypass this
- Controllers in `scripts/server/` are server-only; clients are read-only observers
- **Strict for ship state:** view-side code (`scripts/ui/`, `scripts/view/`, `scripts/core/`) never calls a `ShipStateController` or `EnvironmentController` mutator and never writes a `ShipState` field, even under an `is_server` check or an `SCV:ALLOW` comment. It sends a request the server validates and answers with "" or a reason: `GameState.start_scenario` (game start), `player_submit_plan` (its own player only), `player_clear_movement`, `player_extend_course`, `player_cut_course`, `player_reset_course`, `player_reset_planning`, `player_submit_fire_orders`, `player_submit_bear_off`, `player_plot_crew` (also the boarding order), `player_set_crew_auto`, `player_plot_sail_change`, `player_submit_maintenance_orders`, `player_declare_escape`, `player_set_cast_lead`, `player_send_signal`, `player_cancel_signal`, and for the Developer UI `GameState.dev_commands` (`DevCommands`: server and debug builds only; `reset_game` restarts the scenario). Read-only queries (`get_`/`is_`/`can_`/`has_`, `course_options`, `start_of_turn_course`) are fine. New player actions get a new server request method. `test_server_authority.gd` scans the view code (`scripts/ui`, `scripts/view`, `scripts/core`, `scripts/commands`) and fails `make test` on a violation (including GameState container and log mutators, `phase_controller` field writes, server controllers with no view-facing queries, any `CrewTaskController` call other than the queries `current_plan`, `planned_tack_sections`, `handler`, any `BoardingController` call other than its queries, and writes to `controller_side`, `prize`, `detached_boxes`, `navy`, `value_morale_rating`, `boarding_actions`, `linked_at_plot` or `BoardingAction` fields).

- `EnvironmentController` manages RNG seed for determinism

### Movement Allowance Lookup
- All keys are **strings** (including wind_speed and rigging_quality)
- Wind-facing `"L"` (luffing/into wind) is a special case that always returns 0
- Uses `assert()` for parameter validation — fails fast on bad input
- **Blocked wind** (5.G) is applied on top of the table, never inside it: `BlockedWind` (`scripts/server/blocked_wind.gd`, pure statics) gives −1 MA (never to 0) when every hex directly to windward of the ship (two at WF=C/B, one at WF=R) is held by a ship at FS or above that is not dismasted. `ShipStateController.get_movement_allowance` uses the ships' positions; the movement validator uses the plotted position against the other ships' positions. `DataManager.get_movement_allowance` is the bare table. **Towing** (12.A.7) is applied the same way, on top of the table: `ShipStateController.get_movement_allowance` and the movement validator take `tow_mp_loss` off a tower's MA (never below 0); the 5.E.5 acceleration reduction of 1 applies to a tower too (`speed_change_limits`).

### Known Limitations
- The stub AI's escape steering is greedy (a climb on distance to the permitted edge, no pathfinder), so it can stall behind land or a shoal line between it and the edge.
- The stub AI stalls instead of tacking when the wind blows straight against its approach.
- Not implemented: the optional rules of 14 other than limited information (14.C is in, `PlayerView`; the view does not use it yet and AI captains read full state). Anchoring is in (13.A–F, 7.C.12c, 5.D.4). Milestone 3 items still absent: none known beyond the optional rules above (chase guns are the simple house-rule chasers, medium guns and class 4 ships are in). Everything else of Milestone 2 is in: crew tasks (manual or Automatic), tacking crew, reorganizing, fire and explosions, repairs, marine fire, grappling, boarding, prizes, recapture and multi-ship boarding; `docs/rules/feature_diff.md` has the details.  Also absent from the map work: scattering (Scenario Book V.C), variable reinforcement entry (Scenario 12), special victory conditions (VI.C), and inner boundaries of kind `none` or `escape` (only the four map edges take those; inner lines are `open` for now). Towing is in (12.A; `docs/rules/feature_diff.md` §4–5 for the readings).

### Sea look and ship motion (view only)
- `SeaModel` (`scripts/view/sea_model.gd`, `SeaModel.instance`) is the one sea for the water shader and the ships: sea clock (`advance(delta)` accumulates each swell phase and the chop clock, so speed, wavelength and wind changes never jump them; a wind shift swings the swell round over `DIR_BLEND_SECONDS`; `process_priority` −10 so it moves before the ShipViews ride it), three Gerstner swell components running downwind, zoom `intensity` (0 = flat board at `flat_distance`, 1 = full swell at `full_distance`, smoothstep), `grid_opacity()` (the plain grid fades out between `grid_fade_start` and `grid_fade_end`), whitecaps (from `whitecap_min_sea`), and the preset for the effective sea state loaded from `data/ui/sea_presets.json`. It is fed by `OceanView` and never writes game state.
- `ShipMotion` (pure statics) samples the swell at bow, stern and beams for heave, pitch and roll; `ShipView` low-passes them (time constant by ship class and the preset's `inertia_mult`) and scales by zoom intensity; heel to leeward comes from the wind and the sail carried (none when dismasted or destroyed).
- Movement playback glides each ship through its steps (each ship at its own pace, one clock for the turn: `glide_seconds` per MP of the longest plot), landing exactly on the event hexes. See `docs/environment_shader_integration.md`.
