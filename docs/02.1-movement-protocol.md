# Leeward - Movement Protocol

Describes the server authortative movement protocol used by Leeward to plot ship movement

---

## Movement Plotting Protocol

### Core Concepts

**Plotting Session**: Server-side state machine tracking a single piece's movement plotting. Each session is isolated and identified by a unique `session_id`. Each ship has a unique session that tracks movement selection during PLAN PHASE.

**Session Version**: An incrementing integer representing the number of moves in the current path. Enables idempotency, optimistic concurrency, and undo targeting.

| Version | Meaning |
|---------|---------|
| 0 | Session started, piece at origin, no moves plotted |
| 1 | First hex selected |
| N | N hexes in the plotted path |

---

### Session State Machine

```
                    ┌──────────────┐
     StartPlotting  │              │
    ───────────────►│   PLOTTING   │◄─────┐
                    │              │      │ SelectHex
                    └──────┬───────┘      │ Undo
                           │         ─────┘
            ┌──────────────┼──────────────┐
            │              │              │
            ▼              ▼              ▼
      ┌──────────┐   ┌──────────┐   ┌──────────┐
      │SUBMITTED │   │CANCELLED │   │ EXPIRED  │
      └──────────┘   └──────────┘   └──────────┘
                      (explicit)     (timeout)
```

---

### Request/Response Definitions

#### 1. StartPlotting

Initiates a plotting session for a piece.

**Request:**
```json
{
  "type": "START_PLOTTING",
  "player_id": "<player-id>",
  "ship_id": "<ship-identifier>",
  "request_id": "<client-generated-uuid>"
}
```

**Response (success):**
```json
{
  "type": "PLOTTING_STARTED",
  "request_id": "<echoed>",
  "session_id": "<server-generated-uuid>",
  "session_version": 0,
  "ship_id": "<ship-identifier>",
  "origin_hex": { "q": 0, "r": 0 },
  "valid_next_hexes": [
    {
      "hex": { "q": 1, "r": 0 },
      "metadata": { /* game-specific */ }
    }
  ],
  "can_submit": true
}
```

**Notes:**
- `can_submit`: Whether the current path (even empty) can be submitted. Allows "no movement" as valid.
- `valid_next_hexes`: Empty array means no movement possible from origin.

---

#### 2. SelectHex

Adds a hex to the plotted path.

**Request:**
```json
{
  "type": "SELECT_HEX",
  "session_id": "<uuid>",
  "expected_version": 2,
  "selected_hex": { "q": 3, "r": -1 },
  "request_id": "<client-generated-uuid>"
}
```

**Response (success):**
```json
{
  "type": "HEX_SELECTED",
  "request_id": "<echoed>",
  "session_id": "<uuid>",
  "session_version": 3,
  "plotted_path": [
    { "q": 1, "r": 0 },
    { "q": 2, "r": 0 },
    { "q": 3, "r": -1 }
  ],
  "valid_next_hexes": [ /* ... */ ],
  "can_submit": true
}
```

**Idempotency & Concurrency Rules:**

| Condition | Behavior |
|-----------|----------|
| `expected_version == current_version` | Process normally |
| `expected_version == current_version - 1` AND same hex as last selection | Return cached response (retry case) |
| `expected_version < current_version - 1` | Error: `VERSION_CONFLICT` |
| `expected_version > current_version` | Error: `INVALID_VERSION` |
| `selected_hex` not in `valid_next_hexes` | Error: `ILLEGAL_HEX` |

---

#### 3. Undo

Reverts the path to a previous version.

**Request:**
```json
{
  "type": "UNDO",
  "session_id": "<uuid>",
  "expected_version": 5,
  "revert_to_version": 2,
  "request_id": "<client-generated-uuid>"
}
```

**Response (success):**
```json
{
  "type": "UNDO_COMPLETE",
  "request_id": "<echoed>",
  "session_id": "<uuid>",
  "session_version": 2,
  "plotted_path": [
    { "q": 1, "r": 0 },
    { "q": 2, "r": 0 }
  ],
  "valid_next_hexes": [ /* recomputed for version 2 */ ],
  "can_submit": true
}
```

**Constraints:**
- `revert_to_version` must be in range `[0, expected_version)`
- `revert_to_version: 0` clears the path entirely

---

#### 4. CancelPlotting

Discards the session entirely.

**Request:**
```json
{
  "type": "CANCEL_PLOTTING",
  "session_id": "<uuid>",
  "request_id": "<client-generated-uuid>"
}
```

**Response:**
```json
{
  "type": "PLOTTING_CANCELLED",
  "request_id": "<echoed>",
  "session_id": "<uuid>"
}
```

**Note:** Idempotent—cancelling an already-cancelled or expired session returns success.

---

#### 5. SubmitMovement

Finalizes the plotted path as the piece's committed movement for this turn.

**Request:**
```json
{
  "type": "SUBMIT_MOVEMENT",
  "session_id": "<uuid>",
  "expected_version": 4,
  "request_id": "<client-generated-uuid>"
}
```

**Response (success):**
```json
{
  "type": "MOVEMENT_SUBMITTED",
  "request_id": "<echoed>",
  "session_id": "<uuid>",
  "piece_id": "<piece-identifier>",
  "final_path": [
	{ "q": 1, "r": 0 },
	{ "q": 2, "r": 0 },
	{ "q": 3, "r": -1 },
	{ "q": 3, "r": -2 }
  ],
  "path_version": 4
}
```

**Constraints:**
- Fails with `CANNOT_SUBMIT` if `can_submit` was `false` at current state
- `expected_version` must match to prevent submitting stale state

---

### Error Response Format

```json
{
  "type": "ERROR",
  "request_id": "<echoed>",
  "error_code": "VERSION_CONFLICT",
  "message": "Expected version 3 but session is at version 5",
  "current_version": 5
}
```

| Error Code | Meaning |
|------------|---------|
| `SESSION_NOT_FOUND` | Invalid or expired session_id |
| `SESSION_TERMINATED` | Session already submitted/cancelled |
| `VERSION_CONFLICT` | expected_version too old |
| `INVALID_VERSION` | expected_version in the future |
| `ILLEGAL_HEX` | Selected hex not in valid set |
| `CANNOT_SUBMIT` | Current path state doesn't allow submission |
| `PIECE_UNAVAILABLE` | Piece already has active session or can't move |

---

### Security Properties

1. **Server-authoritative**: Client can only select from server-provided options. Server revalidates on every request.

2. **No client-side path construction**: Client never sends a full path—only incremental selections.

3. **Version binding**: Every mutating request requires `expected_version`, preventing:
   - Replay of old requests
   - Race conditions between concurrent requests
   - Cross-session injection (wrong session_id + version won't match)

4. **Request ID deduplication**: Server can optionally track `request_id` per session for at-most-once delivery guarantees.
