# Towing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Leeward the whole of Close Action 12.A:
- preparing to tow and passing the tow;
- the towed ship following in the tower's wake under proportional movement;
- blocked tows and tow collisions;
- the speed loss;
- cutting, by TX, hull critical #6, and automatically;
- drift as a group, the 9.B.1b exception, and escaping with a tow.

The stub AI plays it, and a view-only minimum draws it.

**Architecture:**
- Two crew tasks (PT, TX) on the existing crew-task engine (Tasks 1, 5).
- Tow state as two ids on the ship (Task 2).
- A pure `TowRules` for legality, geometry and the speed loss (Task 3).
- A `TowController` crew-task handler that rolls tow attempts at the start of the Grappling sub-phase, cuts tows in
  SoP V.B and on status changes (Tasks 5, 6).
- The movement resolver moves the towed ship as a pure function of her tower's resolved steps in each pass
  (Tasks 7, 8).
- Hooks in existing code:
  - MA, plotting, irons and anchoring (Task 4);
  - drift, gunnery, hull #6 and escape (Task 9);
  - PlayerView, the Developer UI and the scenario (Task 10).
- Then the stub AI (Task 11), the view (Task 12) and the docs (Task 13).

**Size:** 13 tasks, under the ~14 limit. If a split is wanted, Tasks 1–6 (state, rules, crew and maintenance) and
Tasks 7–13 (movement, effects, AI, view, docs) are each a coherent branch.

**Tech Stack:** Godot 4.6, GDScript, GUT 9.5. `make test` runs the whole suite. Run `make import` before
`make test` whenever a task adds a `class_name` or any new file. Godot then writes the `.uid` files, which every
commit must include.

**Spec:** `docs/superpowers/specs/2026-11-18-towing-design.md`. Executors read it alongside this plan; section
numbers below (§n) are the spec's. Binding requirements: `docs/superpowers/specs/2026-11-17-subprojects-3-7-decisions.md`
§0 and §4. Rules: `docs/rules/close_action.md` 12.A, 5.D.1b, 5.D.7, 5.E.5, 8.A.6, 9.B.1b, 10.H.2, SoP V.B; Diagram
24 (`docs/rules/images/diagram-24-towing.png`). Invoke the `close-action-rules` skill before game-logic work.

## Global Constraints

- **Directions:** `HexGrid.DIRECTIONS` 0 = E (1, 0), 1 = SE (0, 1), 2 = SW (−1, 1), 3 = W (−1, 0), 4 = NW (0, −1),
  5 = NE (1, −1). `HexGrid.stern_of(bow, f) = bow + DIRECTIONS[(f + 3) % 6]`. Port turn = `f − 1`, starboard =
  `f + 1` (mod 6).
- **Tow geometry (spec §1):**
  - The tow station of a ship to be towed is `towed.hex_position + DIRECTIONS[towed.facing]`. The tower's stern
    must be there.
  - The follow pose for a tower step from (`B`, `f`) to (`B'`, `f'`), with `S = stern_of(B, f)` and
    `S' = stern_of(B', f')`, is: bow `S`, facing `d` with `S + DIRECTIONS[d] == S'`, stern `S − DIRECTIONS[d]`.
- **Test geometry used throughout (wind from 0, speed 3):**
  - Tower `t`: bow (5, 5), facing 3, stern (6, 5).
  - Towed `w`: bow (7, 5), facing 3, stern (8, 5).
  - Tower ahead to (4, 5): `w` → bow (6, 5), facing 3, stern (7, 5).
  - Tower turns starboard to 4 at (5, 5), new stern (5, 6): `w` → bow (6, 5), facing 2, stern (7, 4).
  - Tower turns port to 2, new stern (6, 4): `w` → bow (6, 5), facing 4, stern (6, 6).
- **Task lengths:** PT = 5 ± SK (SK: A −3, B −2, C −1, D 0, E +1, F +2, G +3; CQ C → 4, A → 2, G → 8). TX = 1.
  Each takes one section.
- **12.A.7 loss:** `1 + max(0, tower.class − towed.class) + (1 if towed dismasted or sail_state "NS")`. Classes:
  `frigate_38` 3, `frigate_32` 3, `ship_of_line_74` 2.
- **Tow grapple:** d10 + modifier ≤ 2. Modifiers: ± SK, towing −1, marines not available +1, WS 4 +1, target used
  0 MPs −1.
- **Dice:**
  - tow attempts and hull #6 roll through `game_state.dice`;
  - the movement resolver's tow dice (towed bow depth, ram rigging, ram fouling) come from its own `rng`, inside
    the pass;
  - never call `randi()`;
  - with no tow on the board no die is added anywhere.
- **Enum order:** `PhaseEvents.Type` values are appended after `VEER_IN` in the order `TOW_BEGUN`, `TOW_CUT`.
  `MovementTypes.ResolutionEventType` values are appended after `LEAD_SOUNDING` in the order `TOW_FOLLOW`,
  `TOW_HELD`. Never renumber.
- **Server authority:**
  - every ShipState mutation goes through `ShipStateController`;
  - every server method checks `is_server` and `push_error`s on a client;
  - view code (`scripts/ui`, `scripts/view`, `scripts/core`, `scripts/commands`) only reads, and
    `test_server_authority.gd` must stay green;
  - dev commands are named `take_in_tow` and `cast_off_tow`, so they never match the forbidden mutator names.
- Use `Trace`, never `print()`.
- `make test` is green at the end of every task. No existing test may change its expected values unless the task
  says so.
- The PostToolUse hook runs the full `make test` after edits under `scripts/server/`, `scripts/state/`,
  `scripts/core/`, `scripts/autoload/` and `test/unit/`.
- `docs/rules/feature_diff.md`, `CLAUDE.md` and the scenario-creator skill are updated in Task 13 only.
- **Test fixtures:**
  - Copy the setup pattern of `test/unit/test_anchoring_movement.gd`: save and restore `GameState.dice`,
    `turn_log`, `environment`, `active_scenario`, `current_turn`, `ships`, `ships_by_side` and the phase
    controller's phase and prompt ids.
  - `GameState.dice = ScriptedDice.new()`.
  - Wind direction 0, speed 3.
  - `active_scenario = {"map_bounds": {"width": 40, "height": 30}}`.
  - `_make_ship(id, hex, facing, side := 0, speed := 0, cls := 3)` builds `Ship.from_dict` with the given
    `"class"`, explicit rigging and hull, and `crew_auto = false`.
  - For resolver runs, use `MovementResolver.new(GameState, rng)` with `rng.seed = 12345`.
  - A test that expects no die asserts `_dice.remaining() == 0` after queuing nothing.
- **Commits:** every commit that adds a file also adds its `.uid` (run `make import` first). End every commit
  message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

### Task 3: `TowRules` — legality, geometry and the speed loss

**Files:**
- Create: `scripts/server/tow_rules.gd`.
- Test: create `test/unit/test_tow_rules.gd`.

**Interfaces (Produces):** `class_name TowRules extends RefCounted`, pure statics only. The header `##` cites
12.A and spec §1, §3, §4, §6.

```gdscript
const CODES: Array[String] = ["PT", "TX"]
const STATION := "tow"
const MAX_MPS := 2  # 8.C.1
static func is_code(code: String) -> bool
static func station_hex(towed: ShipState) -> Vector2i            # towed.hex_position + DIRECTIONS[towed.facing]
static func in_position(tower: ShipState, towed: ShipState) -> bool  # tower.stern_hex() == station_hex(towed)
static func follow_pose(bow: Vector2i, facing: int, new_bow: Vector2i, new_facing: int) -> Dictionary
	# {"bow": S, "facing": d, "stern": S - DIRECTIONS[d]} (spec §1); push_error and {} when S, S' are not neighbours
static func ma_loss(tower: ShipState, towed: ShipState) -> int     # 12.A.7
static func parse_order(order: String) -> Dictionary               # {"kind": ""|"cut"|"take"|"bad", "target": id}
static func take_target_error(ship: ShipState, target: ShipState) -> String
static func refusal(ship: ShipState, code: String, accepted: Array) -> String
static func order_task(ship: ShipState, order: String) -> Dictionary   # {"code", "params": {}} or {}
static func pair_error(tower: ShipState, towed: ShipState, setup: bool = false) -> String
static func broken_reason(tower: ShipState, towed: ShipState) -> String
```

- `ma_loss`: `1 + maxi(0, tower.ship.ship_class − towed.ship.ship_class) + (1 if towed.is_dismasted() or
  towed.sail_state.to_upper() == "NS" else 0)`.
- `parse_order`: `""` → kind `""`; `"cut"` → `"cut"`; `"take:<id>"` with a non-empty id → `"take"`, target id;
  anything else → `"bad"`.
- `take_target_error(ship, target)`, in order:
  - `target == null` → `"Unknown ship"`;
  - same id → `"a ship cannot tow itself"`;
  - `target.side != ship.side` → `"only friendly ships may be towed (12.A.2)"`;
  - `target.is_struck()` → `"%s has struck: a ship that has surrendered is not towed (ruling)"` (name);
  - `target.is_destroyed()` → `"%s has blown up"`;
  - else `""`.
- `refusal(ship, code, accepted)`:
  - `not ship.crew_can_act()` → `"the crew cannot act"`;
  - `ship.is_captured()` → `"a prize plots only boarding and repairs (10.H.2)"`;
  - for PT, in order:
    - `is_towing()` → `"already towing (12.A.2)"`;
    - `is_towed()` → `"a towed ship cannot tow (12.A.2)"`;
    - `tow_prepared` → `"already prepared to tow (12.A.3)"`;
    - `"PT" in accepted` → `"one section prepares the tow (12.A.3)"`;
  - for TX:
    - no tow → `"no tow to cut (12.A.9)"`;
    - `"TX" in accepted` → `"one section cuts the tow (12.A.9)"`;
  - any other code → `"not a towing task"`.
- `order_task(ship, order)`:
  - `take` gives `{"code": "PT", "params": {}}` when not towing, not towed, not `tow_prepared` and
    `ship.tasks_with("PT")` has no live task (`ended == ""`);
  - `cut` gives `{"code": "TX", "params": {}}` when towing or towed;
  - else `{}`.
- `pair_error(tower, towed, setup)`, the checks and messages of spec §4, in that order (use `ship_name` in
  messages).
- `broken_reason(tower, towed)`, in order:
  - `"destroyed"` (either `is_destroyed()`);
  - `"struck"` (either `is_struck()`);
  - `"aground"` (either `is_aground()`);
  - `"taken"` (`tower.is_captured()` or `towed.side != tower.side`);
  - else `""`.
