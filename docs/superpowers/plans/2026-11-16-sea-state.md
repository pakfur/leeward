# Sea State Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lower-deck guns against sea state (7.F.2) on a 0–5 sea scale, and a production version of the tuned sea spike: one sea model for water and ships, zoom-blended swell, grid fade, whitecaps, heavier ship motion, and a glide playback that lands on event hexes.

**Architecture:** Rules: `EnvironmentState.sea_state` 0–5; a pure `FireGeometry.leeward_side` helper; a `lower_deck_closed` modifier in `GunneryCalculator.preview()`. View: a `SeaModel` node (from the spike's `scripts/view/sea_model.gd`) owns the sea clock, swell, zoom intensity and presets loaded from `data/ui/sea_presets.json`; it pushes uniforms to `ocean_water.gdshader` and is sampled by `ShipView`; `WaveCalculator` is retired. Playback glides per stretch between event segments. Tuning sliders live in the F12 Developer UI.

**Tech Stack:** Godot 4.6, GDScript, GDShader, GUT 9.5 (`make test`).

**Spec:** `docs/superpowers/specs/2026-11-16-sea-state-design.md`. Reference implementation: branch `spike/sea-motion` (`git diff 2e7095c..spike/sea-motion`; worktree `.claude/worktrees/sea-spike`). Adapt spike code, don't copy its SPIKE comments, F9 panel or autoshot.

The developer sea-state override changes the look only, never `EnvironmentState`. `test_server_authority.gd` passes.
- Logging through `Trace`, never `print()`. Rolls: none added.
- `make test` green after every task (1730 at start). Godot APIs: check context7 `/godotengine/godot-docs`.
- After any GDScript/shader edit that the game loads, a launch with zero `game_get_errors` (godot MCP; if port 9090 is held by the user's own editor game, use a headless/autoshot-style check and say so).
- Sea state 0–5: 0 calm (extension, no rule effect), 1–5 as 3.B.5. Names: 0 "calm", 1 "slight", 2 "moderate", 3 "rough", 4 "very rough", 5 "high".
- 7.F.2 with `fb = ship.freeboard`, `ldgm = ship.lower_deck_modifier` (negative): sea < fb nothing; sea == fb → `ldgm` on the leeward broadside only, none at WF=L/R; sea > fb → `ldgm` on every shot. Modifier id `lower_deck_closed`, label "Lower deck guns closed".
- Leeward: `r = (facing − wind_direction + 6) % 6`; r 1,2 → `ShipState.STARBOARD`; r 4,5 → `ShipState.PORT`; r 0,3 → −1 (`wind_direction` = where the wind comes from).

## Review Focus

1. **Equal sea and freeboard at WF=R or WF=L:** no modifier on either side. Task 2 `test_equal_sea_at_reach_has_no_effect`.
2. **Zoomed out (distance ≥ 20.5):** water vertex height and ship motion are exactly zero, so the board reads as before. Task 3 `test_intensity_zero_at_flat_distance` and Task 5 `test_ship_level_when_flat`.
3. **A bear-off pause mid-move:** ships stand on their paused-segment poses and resume from them. Task 6 `test_pose_at_event_segment_matches_resolver`.
4. **Old saves / scenarios with sea_state 0–3:** load unchanged (same numbers), anything above 5 or below 0 is clamped. Task 1 `test_sea_state_clamped_on_load`.
5. **Developer override:** changing the sea look never changes `EnvironmentState.sea_state` or the gunnery modifiers. Task 7 `test_override_does_not_touch_environment`.

### Task 6: Glide playback landing on event hexes

**Files:** Modify `scripts/view/movement_resolution_playback_controller.gd`. Test: `test/unit/test_playback_glide.gd` (pure track-building helpers).

**Interfaces:** `static func glide_stretches(event_segments: Array[int], first_segment: int, last_segment: int) -> Array` (list of `[start, end]` segment ranges, split at every event segment); `static func pose_at(track, t: float)` or equivalent so tests can sample; `glide_seconds` per segment from `SeaModel.instance` preset (default 0.8 without a model).

**Approach:** each ship's move is split into stretches ending at every segment that carries an event (collision, contested hex, overlap rollback, stern contest, bear-off pause); within a stretch the ship accelerates and decelerates (the spike's trapezoid), arriving exactly at the resolver's pose for the stretch's last segment; the event pause plays; the next stretch starts from that pose. Stretches without events are one continuous glide. The bear-off resume (`resume_impulse`) restarts from the paused segment's poses.
